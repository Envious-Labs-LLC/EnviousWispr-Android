   170	## 3. Design
   171	
   172	1. **`PreferenceRead` (proposed), in `SessionPreferencesSource.kt`:** `sealed interface` with `Pending` (proposed),
   173	   `Fresh`, `Failed(val reason: String)` (the reason is a content-free token: `exception:<SimpleName>` or
   174	   `timed_out`; never a message, `#194` territory). `PreferenceRead` exists only inside each
   175	   `AtomicReference<ReaderSnapshot>` and in `PreferenceStart`; no separate outcome field is written (round G4).
   176	2. **One atomic reader snapshot per reader** (round G3, G2.1): `ReaderSnapshot` (proposed), an immutable
   177	   value holding the outcome (`PreferenceRead`) AND that reader's values (settings: cleanup options, the
   178	   nullable clipboard policy, the four capture fields, the tips flag; terms: the term list), kept in an
   179	   `AtomicReference`. The collector replaces it whole on every emission (`Fresh` + the new values) and on
   180	   failure (`Failed(exception:<name>)` + the LAST values, never the defaults), so a reader may go
   181	   `Fresh → Failed` without losing its last successful values, which is what §7's "failure after Fresh"
   182	   row and `aFailureAfterFreshUsesLastSuccessfulSnapshot` need. A first-run failure carries the constructor
   183	   defaults (`CleanupOptions()`, empty terms, `clipboardPolicy = null`, auto-stop off, `InputDevicePick.AUTO`,
   184	   tips on, earbuds hold on). A reader whose flow COMPLETES before its first emission (coverage B1) becomes
   185	   `Failed(completed_without_value)` at once from the collector's normal exit. The eight `@Volatile` fields
   186	   become reads of the current snapshot (the notification's live `clipboardPolicy` read stays, §3.7).
   187	3. **`awaitAnswers(boundMs)` (proposed) replaces `awaitReady`:** each reader's `CompletableDeferred<Unit>`
   188	   signals only that a FIRST answer exists (completed once, by the collector, after the snapshot is
   189	   replaced); it carries no value. ONE `withTimeoutOrNull(boundMs)` encloses both waits under a single
   190	   2 000 ms deadline (round G3.1) and never writes a reader (round G3.2). After the wait, `awaitAnswers`
   191	   makes ONE atomic read of each reader's snapshot and builds `PreferenceStart` (proposed) from those two
   192	   reads alone: outcome and values always come from the same snapshot, so there is no torn state (round G3,
   193	   G2.2). A snapshot still `Pending` at that read yields the caller-local `Failed(timed_out)` with the
   194	   snapshot's (default or last) values; a first emission that lands between the deadline and the read is a
   195	   `Fresh` answer for this take, consistent with its own values (a deviation from the round-3 wording
   196	   "a timeout retains pre-emission values": the value read and the outcome read are one read, which is the
   197	   property the finding protects; excluding a real late answer would need a second read). Later emissions
   198	   replace the snapshot for later takes only. It never returns "not ready".
   199	4. **`beginSession`:** `awaitAnswers` under `SETTINGS_ANSWER_BOUND_MS` (proposed) (2 000 ms,

   202	   `take` / `settings_fallback` (proposed); then the matcher is compiled from `start.terms`, the policy is
   203	   loaded, the journal admission is awaited, and `freeze(start, matcher, policy)` builds the take's
   204	   `SessionPreferences` FROM THE RETURNED START ALONE: `beginSession` never rereads `structuredTerms` or any
   205	   live source field after suspending (round G2, G1.1: `freeze` runs after the compile, the policy load and
   206	   the journal wait, so a post-deadline emission would otherwise replace the live fields first). The
   207	   `showError(SETTINGS_UNAVAILABLE)` branch is deleted.
   208	   **The four capture fields are frozen with the snapshot** (round G2.1): `SessionPreferences` gains
   209	   `autoStopOnSilence`, `silencePauseSeconds`, `inputDevicePick`, `keepEarbudsReady` and `showBluetoothTips`,

   212	   late emission after the bound cannot change a take already started. `takeFacts.inputDevice` (`:334`) is
