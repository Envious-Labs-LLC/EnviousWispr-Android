## 0. TLDR

Add an optional bounded encrypted audio spool during capture. After an abnormal app exit, attempt the orphan once using the existing local speech engine and frozen deterministic processing context. Save produced text to History once, with recovered provenance, never paste it. Cancellation/deletion are committed dispositions, distinct from requesting native cancellation. The service doing recognition owns encrypted-input reads, avoiding client plaintext scratch and a new retirement-acknowledgement protocol.

## 3. Design

### 3.1 Protected bounded store

RecoveryAudioStore (proposed) owns format, fixed slots, owner claims and durable dispositions. It lives in a focused recovery package because those policies cross capture/ASR/History; it owns no session, model, editor or decoder queue. Alternative client scratch/PFD input was rejected because stalled client transport retains plaintext resources. Existing main session and History recovery remain the orchestration owners.
Use ordinary application noBackupFilesDir and existing backup-disabled policy. AES-256-GCM audio frames and frozen context use a separate per-take AndroidKeyStore alias, provider-generated IVs,128-bit tags and canonical AAD. AAD binds version/kind/take UUID/context identity/sequence/start sample/count/length. Authenticate context before interpreting it; publish each frame plaintext only after its tag verifies. Stop at the first torn/bad frame and retain only the earlier contiguous authenticated prefix. This does not detect rollback or truncation to an earlier valid prefix.
Never recreate a missing key for old ciphertext, reuse provider-secret aliases, require StrongBox/user authentication/unlocked-only keys, or downgrade to plaintext. Key failure bypasses protection, not recording. No physical secure-erasure claim. Recovery files, keys, frozen context and dictated content are excluded from diagnostic/feedback bundles and automatic telemetry; diagnostics use only content-free closed outcomes. Verify the actual exported bundle, not only a logger allowlist.
Two fixed record slots. One stable global store.lock inode and fixed slot-0/slot-1 main/audio/ASR lock inodes are created once and never replaced or unlinked on slot reuse. Mutable slot-state files use write/sync/atomic-rename/directory-sync under store.lock, never replace a lock inode. Per process, a synchronized channel registry opens at most one channel per lock inode; do not close a second channel and accidentally release another local claim. Close a channel only after its last local lease/operation ends, with no idle polling or retained model. Failed closure remains uncertain ownership. A checked UUID/generation distinguishes occupants. Same-process coordination accompanies OS file locks. Global metadata coordination is acquired before nonblocking owner claims in fixed main/audio/ASR order; conflict releases acquired resources and defers. No claim wait, crypto, key operation or deletion while holding metadata coordination. No capture/UI thread waits on any store lock.
Publish the initial complete allocator ledger durably before any key generation. Each of its two slots accounts for every creation authorization until logical retirement is durably recorded. Reserve before creation; persist KEY_CREATE_MAY_HAVE_RUN before the sole invocation. Use never-reused store UUID/generation/take identities and refuse counter exhaustion. Never reissue an ambiguous creation or forget its reservation. Key generation stays outside metadata coordination under the main claim, retained through actual local call exit and durable settlement. Cancellation cannot release a still-running creator. Persist observed successful creation before releasing that claim. Late completion rechecks exact identity/disposition and cannot recreate a sealed/deleted slot.

A generic creation exception, process death or missing completion receipt remains UNKNOWN and capacity-bearing. No automatic UNKNOWN reclamation is selected for an unqualified supported backend. Positive expected SecretKey retrieval can fence publication only under a separately qualified single-publisher contract; Android16 source inspection alone is not a portable all-OEM authority. Such a path would require a durable KEY_PUBLICATION_SETTLED receipt before deletion. Without that qualification, retain UNKNOWN instead of adding absence, timeout or reboot exceptions. Two ambiguous reservations may disable new optional protection while ordinary dictation continues.

For positively never-issued reservations, fence every issuer before retirement. For recorded successful creation, terminal disposition and all owner claims precede deletion; normal deleteEntry return acknowledges logical removal, not physical secure erasure. Persist that receipt and finish required file/claim cleanup before slot reuse. Lost acknowledgement can retry only after creation is positively settled; alias names are never reused. Failed cleanup retains capacity. False containsAlias, zero size, empty/truncated enumeration, null getKey and query errors never prove namespace health or remote quiescence. Enumeration supplies positive anomaly evidence only; positively observed unowned aliases quarantine allocation without guessed deletion. A missing ledger with prior coordination/state evidence is not fresh initialization. Unknown/corrupt ledger refuses new allocation. The bound covers preserved non-rolled-back allocator history, not deferred KeyMint GC blobs or unqualified data-reset/reinstall/rollback/power-loss discontinuities.
Unknown-format or malformed occupants count toward capacity and are not silently evicted. Full capacity skips new protection. No age TTL. Explicit History Delete all snapshots current slot/pending identities and retires those after its deletion transaction; future takes are independent. Unknown envelope identity never becomes a guessed key/path deletion.

### 3.2 Proposed budgets and capture feed

Derive audio cap from RecordingLimits.MAX_AUDIO_BYTES: current600seconds x16000samples/second x2bytes =19,200,000bytes. Proposed frame payload32768bytes; maximum586frames at that cap. Require serialized framing overhead <=128bytes per frame, context <=16MiB and metadata <=65536bytes. Maximum encoded record36,117,888bytes; two records72,235,776bytes. These are proposed arithmetic budgets, not measured runtime performance.
The context cap deliberately permits fail-open refusal for an oversized valid dictionary; never truncate/rewrite words to fit. No claim every possible dictionary fits. Prove exact encoding bounds, multi-byte inputs, framing overhead and arithmetic before wiring. Existing repository bounds are2000terms AND2000total aliases, not256aliases on every term simultaneously.
RecoveryAudioWriter (proposed), owned by the capture session, uses a preallocated bounded handoff, proposed64x1024byte blocks plus one32768byte assembly buffer. No new allocation, disk/crypto/Binder call or consumer-held lock in the capture loop. Slow/full/failed feed disables that take's protection at a frame boundary and keeps ordinary capture working. Do not bridge a missing sample range.
Prepare independently from ordinary start. Attachment carries only checked slot/UUID/generation/context identity, not large context. Until attachment actually owns the matching open take and audio claim, words are not claimed protected. A late attachment may protect only the later admitted prefix; persist its actual first-sample position and recovered duration honestly. Scanner and attachment serialize phase+claim transitions so sealing wins over late attachment, or an actual writer claim makes scanning defer. Never create files/keys during a late attachment.
Sync complete authenticated frames and necessary directory metadata on the writer. Prefix survival depends on actual completed syncs; no promised time-to-durability or power-loss guarantee. Actual writer close releases audio ownership; requesting stop is insufficient.

### 3.3 Frozen effective context

FrozenRecoveryContext (proposed) contains original identity/time, PCM format, format/recipe provenance, exact effective CleanupOptions and exact ordered CustomTerm values used by the successful matcher, plus the independently frozen spellingProtectedWords. Persist neither Matcher/TakeContext objects nor editor/clipboard/provider credentials.
Carry successful matcher input alongside the prepared result; failure freezes an empty effective list, retaining the real protected-word fallback. Use a versioned bounded binary context codec over standard data input/output primitives, preserving Kotlin UTF-16 code units, all admitted field values and order without export normalization/collision filtering. Check each count/length and aggregate byte budget before allocation; bound terms/aliases against current authoring limits plus admitted built-ins, and bound protected-word entries/aggregate characters independently. Unknown tags, invalid numeric/enum values or over-budget contexts refuse protection. No generic Java object serialization or unbounded JSON tree. VocabularyExport identity alone is insufficient: it omits usageCount and normalizes inputs. Unknown context versions defer. No silent use of current settings after upgrade.
Reuse/extract the existing deterministic fallback path from TakePolishController, including its safe vocabulary restoration and language policy. Last-good text survives cleanup failure. Replay never invokes local/cloud AI polish or any insertion/finalizer-delivery path. Current usable compatible speech model may differ after upgrade; record what actually ran, never download an old model automatically.

Recognition and deterministic transformations are shared with an explicit recovery content-logging policy disabled. Recovery must not invoke word-bearing callbacks or evaluate lazy word suppliers, even when Detailed Log is On. Apply the policy at AsrService raw_speech and the extracted TakePolishController vocabulary/cleanup trace sites, before any content enters LocalLog, not as later ZIP filtering. Existing ordinary Detailed Log behavior remains unchanged. A closed request/content-trace capability chooses this policy; no runtime setting or test switch weakens it. Recovery exceptions map to approved content-free outcomes, never transcript/context/vendor prose. Extract the deterministic transformation independently of its ordinary logging collaborator, preserving its last-good-text decisions.

#### Version1 context wire inventory

Use big-endian fixed integer primitives. Header:8-byte ASCII magic EWRCTX01, unsigned16 version1, UUID as two64-bit words, signed64 original creation time, signed32 sample-rate/channels/bytes-per-sample (must match supported PCM), then bounded recipe-format/provenance strings. Strings are signed32 UTF-16 code-unit count followed by exact unsigned16 units; reject negative/over-budget/truncated lengths before allocation. No normalization or lossy UTF-8 conversion. Nullable values use byte0=null or1=present, so null and empty stay distinct. Booleans are exactly0/1. Reject unknown tags, nonfinite doubles, impossible bounds and trailing bytes.
Cleanup payload in order: removeFillers, spokenEmoji, spokenPunctuation (boolean bytes), englishSpelling tag0=AMERICAN/1=BRITISH, protected-word set count followed by strings in unsigned-code-unit lexical order. This preserves set membership with deterministic bytes. Terms are an ordered count/list; each term writes spelling, ordered aliases, nullable category, signed32 priority, forceReplace, caseSensitive, nullable IEEE754binary64 minSimilarityOverride, signed64 usageCount, imported. All CustomTerm fields are represented. Bound field/count/aggregate allocations against actual admitted authoring limits plus built-ins and protected-word generation, as well as16MiB total; unexpected values refuse protection.
Context digest is SHA256 over the exact canonical plaintext context bytes; it is included in authenticated envelope AAD and must match after decrypt. Audio frame first-sample position is independent of context preparation. Frame envelope is fixed-width:8-byte ASCII magic EWRAUD01,32-bit version1,8-bit record-kind (1=context,2=audio,3=completed-capture footer),128-bit UUID,64-bit generation,256-bit context digest,64-bit sequence,64-bit absolute start sample,32-bit sample count,32-bit payload length,96-bit provider IV, ciphertext and128-bit tag. Integer payload/count relationships and total bytes are checked before decrypt; fixed overhead121bytes fits the128byte budget. Context kind uses sequence/start/sample-count zero and its bounded context payload length. Audio kind requires sample-count x2=payload-length and contiguous absolute sample intervals, with sequence startingzero. Footer kind has no payload: sequence equals audio-frame count, start equals the exclusive final captured sample, sample-count equals total protected samples, and that end must equal first authenticated sample plus the contiguous sample sum. Emit a footer only after actual capture closure and complete writer drain with no dropped range. Footer bytes count inside the65536byte metadata allowance. Reject duplicate/trailing frames after a footer; a context-only record is not speech. No kind is interpreted as another.
Independent literal byte/value fixtures cover NUL, lone high/low surrogates, supplementary pairs, null/empty, order, every option/term field, min/max numbers, malformed lengths/tags/overflow/truncation/trailing data, unknown version and over-budget legitimate input. Exact round-trip and deterministic cleanup/vocabulary output are separate oracles.

The isolated context codec uses current authoring bounds of2000user terms/2000total user aliases/256aliases per term/200UTF-16units per term field, plus the admitted built-in population. Protected-word membership is frozen separately, canonically sorted by UTF-16 units and never normalized. Its count bound is2000x201, with an independent8192unit per-word recovery admission cap and the16MiB aggregate encoding cap; unexpected larger input bypasses protection without truncation. Recipe and format-provenance fields each admit256units. These are recovery admission limits, not a Unicode-expansion theorem or a claim every future dictionary fits. The writer measures before allocating one exact encoded buffer; the reader checks remaining bytes and bounds before each allocation. The codec carries no encryption/persistence/AndroidKeyStore proof; its enclosing authenticated context frame must be verified before decoding.

### 3.4 Eligibility and one attempt

Application-owned HistoryRecoveryCoordinator remains the only startup recovery orchestrator. Its existing recover()/Outcome remains text-only and bounded: DictationSessionCoordinator initialization calls it without waiting; HistoryViewModel initialization awaits only stale-row/word rescue before pruning. Neither caller automatically starts native audio replay. Audio work is a separately bounded asynchronous subordinate, not included in that awaited Outcome and never promoted to its generic History error.
SettingsActivity paired onStart/onStop commands create/close a foreground epoch without retaining an Activity in the recovery limb. App entry requests audio recovery; explicit History navigation/reopening requests it even when the ViewModel already exists. Record admission closes the epoch's replay admission immediately. On stop/config recreation revoke old publication/progress; a new epoch coalesces with actual outstanding work and cannot duplicate an attempt. Ordinary terminal events request cleanup only, never another native replay.
For simultaneous foreground/History requests coalesce one pass per current epoch. Choose at most two eligible slots oldest-original-time then UUID; reserve the next only while the epoch is still visible, ordinary work/model mutation idle and the prior transport episode actually settled. Busy/unknown ownership defers without reserving an attempt; require another explicit foreground/History event instead of an idle retry. The app remains usable while a previous storage operation is still outstanding. Existing saved-text rescue runs first. Audio replay is requested only on explicit app foreground/History opening while ordinary dictation and model mutation are idle; no idle polling/background worker/microphone use.
Acquire main/audio/ASR claims nonblocking to establish an orphan, then seal its armable phase atomically. Retain the main replay claim, releasing audio/ASR claims after sealing so the service can acquire its own reader claim; cleanup requires all three. Actual first-sample position belongs to the authenticated audio frames, not a main-prepared context that cannot know late attachment timing. Existing nonblank History/rescued text, committed user tombstone, live-ending disposition, spent attempt, unsupported format/context, unavailable model or unknown query result suppress/defer audio decode as appropriate. Absence is accepted only from a successful authoritative query.
Persist ATTEMPT_RESERVED (proposed state) with a fresh nonce before any recovery-induced binding/load. It is permanently spent after preemption/failure/unknown, including a crash before bind. Never retry an ambiguous submission or automatically reset eligibility.
The service atomically and durably consumes that exact authorization to NATIVE_CONSUMED (proposed state) before reader work. Duplicate requests cannot both decode. Missing nonce, previous consumption, stale generation or tombstone refuses; never recreate metadata. A failed consumption commit permits no reader work. Main's earlier spent evidence still prevents a restart loop.

Detach frozen context/PCM/result-publication references on preemption; outstanding transport retains only small identity/control state, no model permit. Expose local port-drained settlement only, never label it native retirement. Recording and model maintenance must not await it.

### 3.6 Discard, represented endings and deletion

For a take with a reserved/armed/unknown recovery record or pending arming, reserve cancellation/publication ownership immediately, revoke preparation/replay/AI delivery and stop capture immediately. Off main, a repository/DAO transaction tombstones the take even without a row and removes its draft atomically. Observe actual commit through the existing application write queue receipt; accepted enqueue/timeout is not persistence. Logical store disposition prevents late attachment; database tombstone is the authoritative replay/late-text barrier. Room remains main-owned: audio/ASR inspect store dispositions and do not add database instances. If store revocation fails after the DB commit, an already-issued old service call may do bounded wasted work, but main eligibility/publication transactions still refuse that tombstoned take. Test this split-commit failure explicitly; confirmed discard is replay suppression, not proven physical erasure.
A positively sealed never-reserved take with no pending arming follows the existing ordinary Cancel path; do not add a storage wait when recovery cannot later appear. For potentially protected takes, confirmed Cancel feedback/close follows both safe capture closure and committed discard. Observe using existing finite storage/capture failure bounds without blocking main. If capture is safely closed but discard is unconfirmed, keep publication revoked and say “Recording stopped. Couldn't confirm it was discarded.” If capture closure itself is unsafe, retain its existing microphone failure notice; never claim recording stopped. Pending application-owned work may settle later without a second terminal/stale notice. Crash before acknowledgement can leave unacknowledged recoverable audio; acknowledged committed discard cannot revive.

A wordless/error ending does not receive confirmed discard/cleanup feedback before durable NO_REPLAY. Successful text delivery does not wait for optional physical cleanup; existing saved words/rescue remain the replay barrier.

If unknown/corrupt envelope identity or a failed store query prevents a complete Delete all snapshot, refuse before its DB transaction and show the existing deletion error instead of claiming everything cleared; individual known-row deletion remains available. Never guess an opaque occupant's take/key identity. The same DB transaction tombstones them; new takes after the snapshot are independent. Only committed deletion requests key/file cleanup. Replay save checks tombstone in its own transaction. Failed deletion leaves data and protection intact.

## 3b. Ownership justification

RecoveryAudioStore owns cross-process record policy because the inspected temporary-PCM and text-rescue owners do not own a protected audio record. AudioCaptureService owns its optional writer because only it knows admitted PCM and actual close. AsrService owns replay input because only its worker can prove use ended. HistoryRecoveryCoordinator owns launch orchestration and existing repository/RescuedWords own text settlement. The alternative of a new session/retry/native manager duplicates existing authorities and is rejected.
