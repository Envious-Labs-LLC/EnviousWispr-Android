   184	## 3. Design
   185	
   186	1. **Sweep A (mechanical, scripted, one commit).** `scratchpad/191-sweep-visibility.py` inserts `internal `
   187	   before each of the 214 declarations (the 227 minus the 13 framework rows), file by file, at the exact
   188	   line the enumeration names. Compile; where the compiler reports "exposes internal type", make the named
   189	   member of the framework class `internal` too; where a framework-constructed or annotation-processed
   190	   declaration genuinely needs public, add it to `scripts/visibility-allowlist.txt` with the reason. The
   191	   alternative, hand-editing 196 files, was rejected: a script driven by the enumeration cannot skip one.
   192	2. **Sweep B (12 sites by hand, one commit).** Each `else` arm becomes the `Replacement left side` the
   193	   §2.5.1 table names for its site, with the old right-hand side verbatim, so behaviour is byte-for-byte
   194	   the old default for every existing member. The alternative of adding a new "unknown" branch was
   195	   rejected: the point is that there is no unknown branch.
   196	3. **The check, `scripts/check-visibility.py` (one commit).** Scope: `app/src/main/java/**/*.kt`.
   197	   - A: a top-level declaration (the keyword `class|object|interface|fun|val|var|typealias` with its
   198	     modifiers, possibly after annotation lines, and possibly with the name on the next line, coverage
   199	     D2) with no `private|internal` modifier fails unless it is in `scripts/visibility-allowlist.txt`.
   200	     Top-level means brace depth zero: the script tracks `{`/`}` outside string literals and comments,
   201	     never indentation, so an indented top-level declaration is still top-level and an indented
   202	     companion member is not (round G3). An allowlist entry binds the declaration to its file,
   203	     `app/src/main/java/com/envi/wispr/ui/SettingsActivity.kt:SettingsActivity`, one per line with a
   204	     `#` reason, so a new declaration reusing an allowlisted name in another file fails; the shipped
   205	     allowlist is the 13 framework classes. A public companion member is not this rule's population
   206	     (§2.2 non-goal; the compiler's "exposes internal type" handles the 13).
   207	   - B: closedness is read from the ARMS as a set, never from one label (coverage D1): a `when (subject) {`
   208	     block is treated as closed only when EVERY non-`else` arm's left side is a member of ONE app enum or
   209	     sealed type (a bare member name, a qualified one, or an `is` test on a sealed child; the member sets are read from
   210	     the source by regex over `enum class` bodies at any nesting depth and over `object|data object|class|
   211	     data class X : Sealed` children, coverage D3) or the literal `null`; then an `else ->` arm fails. A
   212	     block with a range, a guard, a literal, a type test on a foreign type or a Boolean subject is open to
   213	     the check and passes; the compiler, not the check, is the authority once the `else` is gone. So the
   214	     check is a drift guard for the shape this change leaves, not a type checker.
   215	   - `--root <dir>` scans that tree's `app/src/main/java` instead of the repository's (coverage F2), which
   216	     is how the JVM test runs it on fixtures. Exit 0/1, prints every hit with `file:line`.
   217	   - Phase 3 (coverage E1, E2): `scripts/validate-pr.sh`'s Code block runs the check and records
   218	     `visibility.txt` (always non-empty: the hits, or `clean`), marks `visibility` satisfied only on exit
   219	     0; `OBLIGATIONS` and `REQUIRED["Code"]` in `scripts/check-validation.sh` gain `visibility`, and for the
   220	     Code lane `visibility` must appear in `obligations_satisfied` (a non-empty `visibility.txt` holding
   221	     hits is a FAILED check, never satisfaction); it is never a `skip-note.txt` entry. Older Code runs under `.validation/runs/` lack the artifact and would

   224	     classifier refuses for the session; the replacement line is filed for the founder like the pass rule).

   227	     on the tree and asserts exit code exactly 0; and runs it with `--root` on fixture trees under
