## 3. Design
Independent feedback package for draft validation, durable records, envelope and HTTP transport. Phone form uses native Material3 dialog/sheet with scrolling and keyboard insets, purple bug glyph, feedback message and optional email, Include diagnostics, expandable exact preview, Send. Copy comes from shipping Mac. Thank-you confirms saved for sending, not delivery; offline explicitly says waiting for internet. Close never sends, never clears draft. After successful save clear only the submitted draft revision, so later edits survive. Opening again while a submission saves cannot duplicate it. Full/storage/config failures retain draft. Persist event UUID before first attempt, reuse on retries.
One atomic state document in the app-private no-backup feedback directory holds draft, admission high-water and queued records. One feedback store lock protects read/commit; max 50 reports and 2 MiB. Malformed state is preserved and reported unavailable rather than overwritten; all records stay on disk for recovery. Rejected or paused delivery is visibly reported. One unique work per persisted report (KEEP), network-connected constraint and exponential WorkManager backoff. Recover scheduling by enumerating records at main launch (save and schedule cannot be atomic together); acknowledge save only when file persisted. Worker retains failed payloads: permanent rejection visible and no auto-retry; transient status/network retry; 401/403/404 configuration pause until next launch; honor rate-limit deadlines. No periodic polling and no foreground service.
Diagnostics built only from a closed allowlist: Android app/version/build, OS/API/model, optional canonical install UUID and up to recent bounded take metadata already in journal; never raw exception messages or content-bearing sources. Exact generated bytes are shown and frozen for queueing. Start with basic metadata if journal cannot load; do not block sending without attachment.

## 5. Lifecycle audit
Async populations: draft write, snapshot load, enqueue, HTTP attempt, WorkManager schedule. Interrupted: IO transaction either committed or retained, worker cancellation retries same id; process kill recovers pending records on launch. Deleted: no user-delete operation for submitted records, accepted delivery deletes only its own id. Mutated: submitted context/preview frozen, edits create next draft. Concurrent: ViewModel single-send guard, repository lock, unique work; reopened forms share Activity ViewModel. Absent: no DSN prevents send and keeps draft; no snapshot disables diagnostics only. Stale: opening generation prevents old snapshot or auto-close altering reopened form. Rotation preserves ViewModel; disk restores after process restart. Closing during queued save does not cancel it. Report operations do not call a dictation service.

## 7. Failure by caller
Blank/oversized/invalid email -> form refuses with existing Mac copy, draft retained. IO/full -> Send shows storage/full copy, retained. Offline -> saved locally waiting for internet, worker retries. Empty/wrong-project DSN -> unavailable, no transmission. HTTP 2xx -> own record deleted; 400/413 -> retained rejected with visible warning; 401/403/404 -> retained paused; 429 -> honor server delay; network/5xx -> retry. Closing UI -> submission continues, no old close action affects reopen. Corrupt state document -> preserve the original bytes, show unavailable warning and stop scheduling rather than discard correspondence.

## Grounded round 1 adjudication: all adopted
Delivery serialized by separate shared send mutex (not storage lock), rechecking durable global hold/pause after acquisition; every response hold saved before releasing; each report still unique WorkManager work. Config pause durable per-launch generation: workers compare current launch token and pause token; a new main launch changes token and replays without defeating a same-launch pause.
Admission and draft clearing: one atomic state document contains draft revision, last admitted revision+event id, and pending/rejected records. Admission saves record and clears only matching draft in the SAME atomic write. Delivery removes only record, retaining last admission revision/id so a late repeated Send from the same revision returns the original admission rather than inventing another. Out-of-order draft writes are rejected by monotonic revision; successful admission leaves a cleared revision marker, so old writes cannot resurrect sent text. New edits keep a greater revision. The document is bounded; malformed document preserved with unavailable error (never overwrite unreadable state).
Transport: no redirects, 15-second connect/15-second read, 60-second total request deadline; disconnect on cancellation, propagate CancellationException, retain report. Shared send mutex is cancellable and releases in finally; one worker per record may retry the same id, remote delivery not exactly-once claimed. Use HTTPS only with the verified Android organization ingest host and Android project id; verify runtime DSN id, never URL from stored record.
Unicode: Android ICU character BreakIterator in production; pure validation accepts a grapheme-count function for JVM tests (JDK regex extended graphemes). Instrumented real Android rows for combining marks/flags/family emoji must pass; no claim from Android stubs.
Worker publicly constructible with exact visibility allowlist entry. All other declarations internal/private.

## Grounded round 2 adjudication and exhaustive class sweep
Adopt both. Admission marker is a HIGH-WATER mark: revision == admittedRevision returns saved original event id; revision < admittedRevision returns stale without any new id/record; only greater revisions can admit. Disk draft save refuses revisions at/below admittedRevision, except the atomic admission transaction may write the cleared draft itself. Test 1 admit -> deliver -> 2 admit -> stale 1 after restart; no new UUID.
Response settlement: under shared send mutex install global hold/pause/unsettled in memory as soon as headers exist. NonCancellable IO commits accepted removal + response hold atomically; no suspension before installing the memory restriction. Atomic commit failure retains the original record, latches process-wide unsettled and refuses every new send until a later settlement succeeds; worker retry uses same report id. Worker cancellation cannot release mutex between received headers and this transaction. Envelope request has its own 60-second deadline and disconnect cleanup; response settlement is small local IO (bounded document size), not another network task. On restart the last committed state remains authoritative; interrupted transport retries original id, no exactly-once remote guarantee.
Class root: stale/incomplete durable state being mistaken for permission to create or send. Full producer enumeration: draft update -> admission -> work scheduling -> worker load -> preflight/global wait -> HTTP connection/upload/wait -> response restriction install -> durable response settlement -> worker result -> startup recovery. For each: Interrupt retains committed state/id; Delete can only be accepted own-record removal; Mutation freezes submission fields, rejects stale draft rev; Concurrent uses FIFO single feedback UI owner + file lock + send mutex; Absent config/storage fails closed while optional snapshot fails open; Stale rev/late presentation/cancelled response cannot create a new admission/send. Shared feedback UI owner follows Mac FeedbackSubmission.shared, application-scoped, contains no Activity/Compose references, snapshot generations and a process scope; AppShell only collects/opens. Store and transport remain independent.
