At commit `2f6bd5f`, the split has a workable shape. These are the statement orders I checked against the current service:

| Callback | Today | Planned |
|---|---|---|
| `onServiceConnected` | `super` → publish → configure events → create overlay once, set position callback, start, collect look, register audio callback, read inputs → log → cancel discovery → guarded post → launch stop-marker read, position load, main-thread post | Same sequence through `bubble.attach()`, `bubble.discoverOnConnect()` and `bubble.restorePosition()` |
| `onInterrupt` | Warn → copy pin package to pending → log outcome → copy/announce → clear pending → clear pin → remove insertion retry → reset retry flag → cancel discovery | Warn must remain first; `runner.abandon()` performs the pending steps and retry removal → tracker clears pin → bubble cancels discovery |
| `onUnbind` | Conditionally retract binding → mark clean → cancel discovery → `super` | Same, with bubble cancelling discovery |
| `onDestroy` | Conditionally retract binding → cancel look collect → unregister audio → stop/null overlay → remove/reset insertion retry → cancel discovery → pending package/log/announce/clear → cancel `historyScope` → clear pin/target → mark clean → `super` | Same grouped into `bubble.close()`, `runner.close()`, `historyScope.cancel()`, `tracker.close()` |

The two declared swaps are the only relative order changes **if** those groups keep their internal statement order. Their retry callbacks cannot run between steps of the main-thread teardown. Position work remains on `historyScope`.

**Findings**

- **High**, `docs/feature-requests/issue-217-2026-09-23-paste-service-split.md:73-76,116`: “Publish binding null first” omits the existing instance guard. An outgoing instance must not unbind its replacement. **Drop-in:** “In `onUnbind` and `onDestroy`, retain `if (instance === this) publishBinding(null)` at its current position. Drift Guard (e) checks the guard, not only the call.”
- **Medium**, `docs/feature-requests/issue-217-2026-09-23-paste-service-split.md:66-70,49`: The construction example does not pass `historyScope` to the bubble. The restore description also needs the existing main-thread post before touching the overlay. **Drop-in:** “Construct `AccessibilityBubbleHost(this, mainHandler, tracker, historyScope)`. `restorePosition()` loads on `historyScope`, then posts to `mainHandler` and checks that the overlay still exists before `setPosition`.”
- **Medium**, `docs/feature-requests/issue-217-2026-09-23-paste-service-split.md:74,76,92`: The runner/tracker contract needs the terminal sequence stated explicitly. In the current code, `finish` captures and stores the pin package *before* recycling the pin; teardown does so before logging and announcing. **Drop-in:** “`finish`: clear pending, capture pinned package, set `pending.targetPackage`, clear pin, disable content-change events, log outcome. `abandon` and `close`: set `pending.targetPackage` from the live pin, log, copy/announce, then clear pending. The service clears the pin only afterward.”
- **Medium**, `docs/feature-requests/issue-217-2026-09-23-paste-service-split.md:31,92`: The tracker’s revalidate contract leaves adoption order open. Current `revalidateBubbleField` retains the old remembered target when discovery fails. **Drop-in:** “`refreshFocusedField(discover)` checks the remembered node and focused window first. On discovery, find and log the candidate; only if found, recycle the old target and adopt the new one. Return the resulting field key or absence. The bubble then calls `fieldActivated` or `fieldLost`, followed by `keyboardBounds`, in that order.”
- **Low**, `docs/feature-requests/issue-217-2026-09-23-paste-service-split.md:66-70`: Moved methods use the service’s private `TAG` (`PasteAccessibilityService.kt:112`). The proposed classes cannot read it. **Drop-in:** “Give each collaborator its own private `TAG = "PasteService"` so existing log tags and messages stay unchanged.”

The insertion path otherwise has a valid boundary: the runner can read one pinned token for each `ServiceEditor` operation while the tracker owns its recycling. Keep `requestInsertion`’s refusal order, retry removal, pending assignment, event-mask change, log and immediate attempt; keep each `tryPendingInsertion` branch’s `finish` before clipboard restore or fallback; keep `recordAndAnnounce`’s clipboard result before History/telemetry and Toast. For the bubble, preserve the event branch order and the discovery retry’s generation check, coalescing, absolute deadline and cancellation.
