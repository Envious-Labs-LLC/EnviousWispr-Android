## FACT: the-text-pipeline
Each stage returns text plus an outcome. A stage may enrich text; it may never erase the last valid result.

1. ASR produces raw text and an observed language.
2. Deterministic cleanup applies filler, number and punctuation rules.
3. Vocabulary correction applies exact terms, aliases, case rules and priority.
4. Optional polish runs, local or cloud, under the policy snapshot the session carries; the answer is one
   `PolishOutcome` per request, with a `PolishReason` from a closed set.
5. Output safety rejects blank, truncated, duplicated or meaning-shifted results and falls back.
6. Insertion planning handles capitalisation, spacing, seam de-duplication and the replacement range.
7. Accessibility returns to the tracked editor and picks ONE route before writing: on API 33+ with an
   eligible field it commits through the accessibility input connection (no clipboard, no "Copied"
   toast); otherwise `ACTION_PASTE`; otherwise copy-only with a visible Paste action. It writes once,
   judges success from the editor's text, never the caret, and never uses `ACTION_SET_TEXT` (#141).

**Cleanup and vocabulary run BEFORE polish on purpose**, so their result survives a polish failure.

# Architecture Rules

Instructions only. The map — modules, packages, processes, pipeline, sources of truth — is
[`../knowledge/architecture.md`](../knowledge/architecture.md). The design target is
[`docs/enviouswispr-android-architecture.md`](../../docs/enviouswispr-android-architecture.md); the outcome
contract is [`docs/enviouswispr-android-parity-spec.md`](../../docs/enviouswispr-android-parity-spec.md).
**Both describe where we are going and name types that do not exist. Grep before citing one.**

## FACT: the-laws
| Law | Why |
|---|---|
| Heart path is sacred. | No optional feature may prevent the user getting their words. |
| Process boundaries are real boundaries. | `:audio`, `:asr` and `:polish` bound memory and crash blast radius. |
| Convenience is not justification. | "Easy to wire here" is invalid placement. |
| New shared objects are guilty until proven innocent. | Every coordinator, manager and singleton justifies its existence. |
| Engine independence lives at the adapter seam. | One session owner, never one per surface. |
| Structural drift is a bug. | Architecture regression is correctness debt. |
| Shortcuts must be declared. | Disclose every temporary compromise in the change summary. |

## FACT: heart-and-limbs
**Heart:** trigger, capture, ASR, text finalization, insertion. It must always complete.
**Limbs:** deterministic cleanup, vocabulary, local polish, cloud polish, live preview, history.

**The fallback floor is the LAST SUCCESSFUL TEXT, not raw ASR.** Cleanup and vocabulary run before polish
precisely so their result survives a polish failure. Only empty output falls through to raw ASR.

A limb hands back the last good value. Never an exception that unwinds the session, never `null` where the
caller has no slot for it, and never an empty string as a failure signal — empty is a legitimate
transcription of silence and the caller cannot tell them apart.

Before adding a feature: heart or limb? Owning package? Owning process? Failure mode? Can the heart
continue? Fuzzy answers mean blocked.

## RULE: one-owner-for-the-session
Every entry point issues COMMANDS to one session owner. No surface runs its own recording, transcription,
polish or insertion, and no surface invents its own phase; each renders the owner's state.

When the coordinator replaces today's session service, it lands in one change — old code removed, new code
wired, no shim (`GR-MIGRATION-COMPLETE`).

## RULE: aidl-is-append-only
Reordering, renaming, or changing a parameter list breaks an already-installed app at RUNTIME with no
compile error. Append at the end. To change a signature, bump the interface and keep the old one until
nothing binds it. The separately installed client this protects is the instrumentation APK
(`app-debug-androidTest.apk`), which binds the non-exported services and is not replaced when the
production APK is, so "both ends ship in one APK" is not a reason to delete a transaction.

## RULE: keep-central-types-thin
A multi-domain owner delegates downward, holds minimal state, exposes a narrow surface, and has a
one-sentence purpose. Block unrelated-domain knowledge, and state plus orchestration plus business rules
in one place.

**`ui/AppShell.kt` and `ui/DictationSessionService.kt` are the standing extraction targets.** Take the
sizes rather than citing a count:

```bash
wc -l app/src/main/java/com/envi/wispr/ui/AppShell.kt app/src/main/java/com/envi/wispr/ui/DictationSessionService.kt
```

Growth in either needs a reason and a named extraction target. Add a screen file rather than a section
to `AppShell.kt` (`TranscriptionScreen.kt`, `PolishScreen.kt`, `SettingsPages.kt`, `ModelCards.kt`,
`HistoryScreen.kt`, `DictionaryScreen.kt`, `OnboardingScreen.kt` are the precedent). Since #190 the shell
holds only route state and the exhaustive screen `when`: the top bar, bottom bar, drawer and glyphs are
`AppNavigation.kt` (with `AppRoutes`, the one reader of the saved route names), the shared rows, chips and
glyphs are `SettingsComponents.kt`, and the activity hands the shell one `AppActions` holder of ten
capability groups built inside `remember(viewModel)`; a new callback joins its group, never the root
signature. `ui/AppShellShapeTest` pins all three. The session service's user-facing sentences live in
`insertion/InsertionOutcomeMessages.kt`.

## RULE: isolate-limbs
A limb must not root into app-wide, window, or insertion-orchestration state. Every limb has a deadline, a
failure path, and an unchanged-text fallback.

**Only one heavy inference process is resident by default.** S1-mini and the Parakeet encoder are each
several hundred megabytes; both resident is not a supported state. Unload before switching engines when
headroom is unsafe, and never load a heavy model in the main UI process. Warm-at-connect is the stage 1
default (#72, measured 2026-09-01 on the S26 Ultra only, debug build, so it establishes neither general
S26, release-build, nor other-device safety: a later warm-up did not reduce peak residency and added 0.8
to 3.1 s of wait; table in
`docs/feature-requests/issue-72-2026-09-01-model-residency-decision.md` §11.1.1). The levers that would
reduce residency are releasing the speech model after transcription (#73) and the NPU polish model (#21).

## RULE: gate-on-capability-not-identity-literal
Feature gates read a declared capability, never an engine or provider identity literal. `when (provider)`
is correct only where the behaviour genuinely IS about identity — the privacy disclosure is the legitimate
case.

**Where an identity `when` is legitimate it must be EXHAUSTIVE with no `else`.** A new `PolishProvider`
must break the build at every disclosure and routing site. An `else` turns that compile error into a
shipped wrong privacy answer.

## RULE: own-state-locally
Keep state near its owning domain; never centralise it because many layers read it. The declared sources of
truth are in [`../knowledge/architecture.md`](../knowledge/architecture.md); **a second home for any of them
is a bug.**

## RULE: minimize-visibility
Kotlin defaults to `public`, so the default is wrong. Declare `private`, then `internal`. Only a type
crossing a Gradle module boundary needs `public`.

## RULE: protect-audio-asr-stability
Audio and ASR changes prioritise stability, minimise blast radius, keep rollback clear, and attach measured
evidence from the physical phone. UI coupling to service internals is a warning sign.

**Never do work on the audio callback thread.** No allocation, no logging, no binder call, no lock another
thread can hold. Buffer and hand off.

## RULE: no-idle-cost
At idle: no timer, no amplitude poll, no accessibility traversal, no binder call, no wake lock, no resident
model. Audio levels are PUSHED from the capture process during a session, not polled by each surface. The
accessibility service remembers only the last focused editable node identity and ignores our own windows.

A background poll is a battery regression even when it is cheap, because the standard is zero, not small.

## RULE: insertion-fails-safe-never-silently
One route, one write (#141): return to the tracked editor and pick exactly one route BEFORE writing. On
API 33+ with an eligible field, commit through the accessibility input connection (no clipboard, no
"Copied" toast); otherwise `ACTION_PASTE`; otherwise copy-only with a visible Paste action. Judge success
from the editor's own text, never the caret. Never `ACTION_SET_TEXT`.

**A stale, missing or unsupported target keeps the transcript on the clipboard and tells the user.** It
never inserts into whatever happens to be focused now.

## FACT: there-is-no-sensitive-field-guard-and-that-is-decided
**Founder decision 2026-08-28: EnviousWispr does not special-case password, payment or OTP fields.** If
the user dictates into one, we insert. Three reasons, so no session rebuilds it: Google Play's
AccessibilityService policy requires disclosure and forbids autonomous operation but is silent on field
types (verified 2026-08-28); the same shape was killed on
macOS after a probe showed Secure Input does not block our paste; and as built it refused only the
harmless insertion step while putting the transcript on the SYSTEM CLIPBOARD and still sending it to
history and cloud polish.

Rebuilding it requires new evidence and a guard placed where the exposure is (before cloud polish and
before history), never at the insertion step.

**The code has not caught up:** `paste/PasteAccessibilityService.isSensitive` and
`InsertionResults.COPY_ONLY_SENSITIVE` still divert to clipboard-only. Removing them is
[issue #11](https://github.com/Envious-Labs-LLC/EnviousWispr-Android/issues/11), heart path, so it needs
the review gate and a hardware run.

## RULE: models-are-pinned-verified-and-app-private
Every model descriptor carries a pinned revision and every model file an exact byte count and SHA-256;
`isAvailable` refuses anything failing those or whose URL omits the pinned revision. Ready only after on-device verification;
failed files quarantined, never loaded. Files stay in app-private storage — do not reintroduce a broad
external-storage permission.

## RULE: architecture-definition-of-done
Triggers: Gradle modules, process assignment, AIDL surface, a new coordinator, state ownership, package
boundaries, cross-module visibility, or logic moved across layers. Uncertainty blocks work pending Codex
review (`GR-ESCALATE-CONSEQUENTIAL`).

- **Placement** — correct package and process; ownership explained in one or two sentences.
- **Heart** — the user still gets text when every optional feature fails.
- **Anti-god-object** — no convenience logic in `AppShell.kt` or the session service.
- **API** — narrowest visibility; no service internals leaked to UI.
- **Boundaries** — no upward dependency; no UI type reaching a service.
- **Validation** — unit tests green, plus a hardware run for any heart-path change, with the evidence
  named. Untested edges stated explicitly.
- **Debt** — shortcuts disclosed; follow-up extraction named.

## RULE: parity-work-cites-its-contract-id
Name the `PAR-###` row and the evidence that closes it. Parity is the same user OUTCOME, never a literal
imitation of a macOS mechanism. A row is closed by evidence, not by code existing.

# Testing Philosophy

**Should this test EXIST?** Is it HONEST: `validation-discipline.md`. How to write it:
`android-testing-patterns.md`. How to run it: `android-tooling.md`.

Founder mandate: test the things that must always work; stop paying for scenarios a real user on a
supported phone cannot produce.

## RULE: every-test-declares-which-of-four-things-it-protects
Complete the sentence **"when this fails, the user sees ___."** If you can finish it, it is a Product
Outcome test. If you cannot, it is one of the other three and must be NAMED as such — never counted as, or
cited as, product coverage.

| Class | Protects | Counts as product coverage |
|---|---|---|
| **Product Outcome** | Audio captured, text produced, text inserted, a limb degrading to the last successful text | YES |
| **Drift Guard** | A frozen internal property: Room schema, manifest shape, call-site inventory | NO |
| **Observability Contract** | Log labels and content-free diagnostics | NO |
| **Harness Contract** | Our fakes, fixtures, device scaffolding | NO |

Declare the class in the suite's KDoc; there is no mechanical tag yet, and claiming one exists is wrong.
All four are legitimate. The defect this prevents is ARITHMETIC — counting drift guards as user safety.

## RULE: the-heart-crosses-a-real-boundary-at-least-once
Every heart-path stage has at least ONE test crossing its REAL boundary. Fakes are correct for the other
thousand cases and never substitute for the one.

| Stage | Real boundary | Why a fake is insufficient |
|---|---|---|
| Capture | A real microphone producing non-zero samples | A dead `AudioRecord` reports "recording" and captures silence |
| Transcription | The shipped model decoding a committed clip | Packaging or ABI breaks while a mock still returns text |
| Polish | The shipped model on the real runtime | A runtime init failure is invisible to a fake that returns polished text |
| Insertion | Text landing in a real third-party editor, exactly once | Calling `ACTION_PASTE` proves the call, never arrival |

Only an instrumented test reaches the last two. A unit test that stubs the AIDL service is a Harness
Contract test, whatever it is named.

## RULE: a-public-product-promise-needs-a-binding-test
Any claim about speed, capacity, a limit, or privacy gets ONE test that fails when the claim stops being
true. Name the claim and its source in the test.

The privacy claims are load-bearing here because they bind the Play Data Safety form. A `when` over
`PolishProvider` gaining a member without a matching disclosure row is the shape that ships a wrong Data
Safety answer.

**A promise about a SIDE EFFECT is the axis "speed, capacity, or a limit" misses, and a UI can hide it.** A
deletion claim does not show itself, so it drifts for as long as nobody looks at app-private storage.
Hiding is not deleting.

## RULE: dont-test-what-cannot-happen
Classify REPRODUCIBLE (a real user on a supported phone produces it; state the input) or HYPOTHETICAL
(needs a misbehaving dependency, a hostile value, or an unobserved race).

**Write a case for a hypothetical ONLY when the failure would be SILENT** — wrong text inserted, a
transcript lost, a limb failing without falling back, a key reaching a log. A hypothetical failing LOUDLY
gets a recorded known limit.

The supported platform bounds this absolutely; there is no API 29 scenario and no 32-bit scenario. Devices
without the vendor NPU runtime are a real scenario only once a CPU fallback ships — until then say "not
supported", not "untested".

## RULE: the-rig-decides-where-a-test-lives-not-the-subject
Ask **which existing fixture already reaches this state**, and put the case there. A test filed by what it
is ABOUT lands beside cases that cannot stage it, and the next move is a second rig for a state something
else already stages. The rigs are named in `android-testing-patterns.md`.

**Two ways a fixture misses, and only the first is fixed by moving.** A fixture that reaches its subject
and asserts the wrong thing is repaired in place. A fixture whose subject DOES NOT EXIST in that
configuration cannot be repaired at all — editing the assertion turns it into a passing test about nothing.

**A failing new test must name WHAT IT FOUND**, not merely that an expectation failed.

## RULE: do-not-multiply-independent-axes
Test every BRANCH on one ordinary input, then each special input CLASS at one representative branch. Never
the Cartesian product. A row earns its place only by reaching a different production branch or reproducing
a distinct OBSERVED defect.

## RULE: never-guess-when-the-subject-is-finished
A test learns the subject is done from a signal the SUBJECT fires — never elapsed time, a `delay()`, a
poll, or the harness going quiet.

**A COUNT THAT EXHAUSTS IS INDISTINGUISHABLE FROM THE CONDITION IT WAS MEASURING.** A loop inferring "the
stop never arrived" from a budget running out accuses production code when the harness merely ran out of
budget. Do not close one by raising the cap.

**The same missing signal produces the VACUITY direction, which is worse because nothing goes red.** Flake
and vacuity are one defect wearing two symptoms.

## RULE: a-flaky-suite-earns-no-new-cases-until-its-wait-seam-is-fixed
The next change to a flaking suite is the seam fix. Not a rerun, not a longer timeout, not another case.
**Raising a wait budget is a silent coverage loss unless you name a regression the old value would have
caught and the new one would not.** This bites hardest on device tests, where a real timing bug and a slow
phone look identical.

## RULE: deleting-a-test-carries-the-burden-of-adding-one
Name what it protected, then either why that protection is no longer needed or where it now lives. "It
never caught anything" is not evidence — a good test never catching anything is the expected case. Never
delete or weaken a guard to move a number.

**"Covered elsewhere" quantifies over DEFECTS, not over the runs you did.** The claim that licenses a
deletion is: is there any defect for which this row is the only red one?

# Android Testing Patterns

**How to WRITE a test here.** Whether it should EXIST is `testing-philosophy.md`; whether it is HONEST is
`validation-discipline.md`; how to RUN it is `android-tooling.md`.

## FACT: the-two-source-sets-answer-different-questions
| Source set | Runs on | Can answer | Cannot answer |
|---|---|---|---|
| `app/src/test/` | The JVM, no Android framework | Pure logic: cleanup, vocabulary, insertion text planning, manifest validation, prompt building, settings state | Anything touching `Context`, Room, the Keystore, a service, or hardware |
| `app/src/androidTest/` | The physical S26 Ultra | Room migrations, the Keystore, AIDL services, accessibility insertion, the real microphone, the real models | Nothing about a device we do not own |

## RULE: put-the-case-where-the-fixture-already-is
The scarce things in this suite are the rigs that stage a hard state. Before building a new one, check
whether one of these already reaches it:

| Rig | Stages |
|---|---|
| `PasteTargetActivity` / `ClipboardPasteTargetActivity` | A real focused editable field for insertion tests |
| `VoicePipelineDeviceTest` | The whole heart on hardware, binding `:asr` and `:polish` |
| `EnviousWisprDatabaseMigrationTest` | Room schema versions from `app/schemas/` |
| `SpeakerPlaybackActivity` | Real audio playback into the real microphone |

A test filed by what it is ABOUT rather than by which fixture reaches it lands beside cases that cannot
stage it, and the next move is a second rig for a state something else already stages.

## RULE: a-device-test-declares-its-precondition-with-assume
`VoicePipelineDeviceTest` uses `assumeTrue` for its PCM fixture. Follow that shape for every device
precondition — models installed, accessibility enabled, a fixture present. **Never let a missing
precondition produce a green.**

## RULE: never-sleep-wait-for-the-subject
No `Thread.sleep`, no `delay()` as a settle, no polling loop with a retry budget standing in for a signal.

- Coroutines: `runTest` with a `TestDispatcher`, and advance the scheduler.
- AIDL and callbacks: a `CountDownLatch` awaited with a timeout, counted down BY the callback — the shape
  `VoicePipelineDeviceTest` already uses. The timeout is a failure bound, not the wait.
- Compose: `waitUntil` on a semantics condition, never a frame count.

**A budget that exhausts is indistinguishable from the condition it was measuring.** When a wait times
out, the failure message names what it was waiting for and what it observed instead, so a slow phone and a
real bug are distinguishable in one read.

## RULE: assert-the-editor-not-the-clipboard
Clipboard publication is the FALLBACK path. A test that asserts the clipboard holds the text has verified
the fallback and said nothing about insertion. Assert the target editor's own field content and its caret,
which is what the paste-target activities exist for.

For the back-to-back case the assertion is that the SECOND transcript reaches the editor, with the first
one's text still present and not duplicated. A test that dictates once proves nothing about it.

## RULE: build-the-expected-value-with-a-literal
When asserting that a transformation preserves something, write the expected value out by hand. Building
it by running the same helper the subject runs means both sides get transformed identically and the row
passes against code that does nothing. `VocabularyCoreTest.transferRoundTripPreservesAdversarialText` is
the right shape: hard-coded adversarial input, compared to a hard-coded expectation.

## RULE: adversarial-input-is-a-row-not-a-suite
One representative case per input CLASS — empty, whitespace-only, very long, non-Latin script, emoji,
embedded escapes, RTL, a lone surrogate — at one representative branch, not the Cartesian product.
`VocabularyCoreTest` carries the vocabulary ones; extend it rather than starting a parallel suite.

## RULE: room-schema-changes-ship-their-migration-test
`app/schemas/com.envi.wispr.history.EnviousWisprDatabase/` holds the committed schema JSON, and
`androidTest` includes it as an asset via the `sourceSets` block in `app/build.gradle.kts`. Every version
bump adds a migration and a test that migrates real rows and asserts the data survived. A migration test
that only checks the schema opens has tested the schema, not the user's history.

## RULE: name-the-test-after-the-outcome-it-protects
`exportRefusesToSilentlyTruncateAnOversizedLibrary` says what breaks for a user. `testExport` does not.
Read the name back as a promise, then ask what the WEAKEST input satisfying the assertion looks like; if
that input would not embarrass the name, the assertion is too loose.

## RULE: declare-the-test-class-in-the-suite-header
Each suite's KDoc states which of the four classes it protects. Owner: `testing-philosophy.md`
RULE: every-test-declares-which-of-four-things-it-protects.

## RULE: no-ignore-to-get-a-green
`@Ignore` on a failing test hides a regression under a passing suite. Fix it, or delete it under
`testing-philosophy.md` RULE: deleting-a-test-carries-the-burden-of-adding-one, and say which you did.

3. **P1, REPRODUCIBLE: a wedged `finishTake` still blocks transcription forever.** `DictationSessionCoordinator.kt:895-915` waits synchronously for `finishTakeOrStop`, while `onCaptureSilent` at `:573-592` does nothing in PROCESSING once `endingConsumed` is true.
