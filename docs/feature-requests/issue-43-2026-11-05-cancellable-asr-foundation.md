## 0. TL;DR

Make existing speech requests cancellable and serialize native lifetime across Android service generations. First usable benefit: a cancelled processing take or dead callback client stops abandoned ASR work rather than leaving it running until the old decode bound. Use one process-owned native command lane, per-service model ownership, scoped RunOptions/Kotlin cancellation and existing deadline machinery. No preview/recovery runtime is enabled in this slice; it supplies their qualified cancellation foundation.

## 1. Problem

Application-source baseline c0d1002e (current main adds only the sampler result documents): SpeechWait.close rejects late answers but sends no ASR cancellation (Coordinator1310-1314); IAsrService has no cancel transaction. AsrService owns a FIFO executor/model per instance (53-84); onDestroy265-270 queues release behind work. New service generations can therefore overlap old native work/model lifetime. No new customer incident count is claimed.

## 2. Goals and non-goals

Goals: current Cancel/dead-callback revokes the exact request, old cancellation cannot affect PR500's replacement attempt, native computation retires or its process ends within a declared containment policy, existing residency/unload behavior and eligible healthy-model reuse are preserved, and model mutation remains protected.
Non-goals: crash spooling/replay, live preview display/PCM feed, optional job purpose routing, new model, inference recipe/accuracy/speed tuning, cloud changes, Room/History changes, new cancellation copy or release upload. Do not close #43/#33 from this foundation.

## 3. Design

### 3.1 One process lane, service-owned model generations

Use one process-scoped native command lane for RecognizerOwner in production and in migrated test rigs. Keep each ParakeetEngine service-owned; no global model singleton. The injected lane is borrowed by every generation; close never shuts it down. Test fixtures explicitly retire their fake/process lane after their owners. Do not retain a second owning-executor mode or obsolete constructor path on an unproved external-client premise. LOAD is a generation-entry barrier, actual free/RELEASE a generation-exit barrier; priorities never cross them.
A generation closing atomically refuses later admission, cancels its queued work, requests active-work cancellation, then frees on the native lane. A later generation cannot initialize until actual old free and close-grace completion won their race. The process owns executor/watchdog scheduler lifetime; an instance close must not shut the shared resources down. Native/session/options cleanup failure cannot count as free or retired: attempt all required closers, surface incomplete cleanup to the same watchdog authority, poison further native admission and end the process. This includes partial model construction; do not infer actual free merely because current TdtModel.close/open cleanup swallows a close exception. No second resource-failure manager. Parked daemon threads do not keep a model resident or poll at idle. Cancelled deadline jobs leave the shared scheduler queue promptly; no timer work remains once all owners/requests are idle.
The existing AsrWatchdog remains the one ending/poison authority and shared-lane admission consults it. Extend its scoped use of EngineDeadline instead of inventing an independent “safe to run” flag that can disagree with deadline expiry. Normal load/decode/release bounds remain owned by AsrBounds.

### 3.2 Exact request identity and compatible transport

Append cancelTranscription(String takeId, IAsrCallback callback) (proposed) at the END of IAsrService. Key request entries by the pair of exact takeId and callback.asBinder identity; takeId alone is insufficient because PR500 reuses it with a fresh callback on retry. Unknown/already-retired/null-callback cancellation is an idempotent no-op, never “cancel every request for this take.”
Register the entry synchronously before enqueueing work. Link nonnull callback Binder death to this entry's cancellation. Retain its identity until the whole task retires, not merely until native returns or result delivery starts. Remove the death link after retirement. Delivery authorization competes with cancellation under that entry: an already-authorized wire delivery cannot be unsent, but the main attempt/publication guards still reject it after user cancellation. Empty legacy take IDs remain valid paired with their callback; null-callback legacy requests retain the existing worker execution/owner-close bounds but cannot obtain callback-death cancellation.
Preserve the four existing AIDL transactions/signatures and the POSITIVELY observed test-client ABI: PipelineBindings.Companion.speechProxy(IAsrService,Function1):SpeechLink, SpeechLink.transcribeFileForTake(String,String,SpeechListener):void, and the unchanged three SpeechListener callbacks. Do not infer an external ABI for internal RecognizerOwner constructors or model helpers; migrate their main/JVM consumers to one current path.
Add prepareFileForTake(path,takeId,listener) (proposed) to the current SpeechLink contract, returning SpeechSubmission (proposed), an opaque prepared request with submit/cancel operations and exact callback identity. Update all current main/JVM implementors and rigs together. An optional CancellableSpeechLink subtype is not justified by the unsupported older-fake-implementation premise. Retain the observed v1 method as a real compatibility entry into the SAME prepared submission core; submit before returning so its synchronous exception behavior remains. The factory return descriptor stays SpeechLink.
Create/attach the prepared submission before calling submit inside the existing off-main request try/catch. Preserve DeadObjectException -> onSpeechLost(attempt) and other-exception handling at Coordinator975-984. Cancellation commands use a narrow PipelineBindings-owned lane, matching the capture-command pattern and outliving service-coroutine cancellation. Cancel before submit prevents send; cancel during registration is latched/re-sent after registration. Close drains issued submissions and latched cancels before shutting their transport lane; no in-flight registration may lose its pending cancel. Retire completed listeners/handles; do not retain them indefinitely.
SpeechWait stores the opaque handle with its exact Attempt under the existing lock. Attaching to a closed/superseded attempt immediately cancels that handle. close/disconnected/expiry capture and clear their own handle under the lock, then cancel outside it; a replacement claim cannot inherit it. A normal accepted answer closes acceptance/deadline but transfers its exact handle to one answered-tail slot in SpeechWait, without immediately cancelling useful cleanup. Later close captures and clears that tail under the lock, cancels outside it, and still returns false for an already-answered wait, preserving PCM deletion ownership. finishSession and destroy close this wait before pipeline unbind. Callback receipt is not server retirement: AsrService235-253 can still run the legacy sweep while keepalive retains the service. No new retirement callback or global completed-handle registry. Current UI cancellation and final publication arbiter remain authoritative and immediate.


### 3.2a Prepared-submission state/event enumeration

Conceptual transport/delivery labels below are Prepared, Submitting, Registered, CancelPending, Cancelled and Finished(callback-or-throw). This is an event table, not a six-value implementation enum: delivery completion and request-return/cancel obligations must be carried as distinct sealed states so early callback followed by close cannot lose its post-return cancel. Do not encode their valid combinations as independent Boolean flags. Preparation allocates identity only: it does not submit Binder work, validate the recording or emit callbacks. These states describe transport/delivery, not native completion. Registered means the synchronous request returned; Cancelled means local delivery revoked, not that the engine retired. A terminal failure callback can arrive BEFORE request return: AsrService146-166 immediately reports a missing file, and SpeechCallbackDeviceTest55-81 exercises that exact producer.

| Event / actual producer | Prior state | Next state and action |
| --- | --- | --- |
| submit, current request worker | Prepared | Submitting; issue one Binder request outside the state lock |
| duplicate submit | Any other state | No second request; return/refuse the duplicate locally |
| cancel, proxy close, SpeechWait close/disconnect/expiry | Prepared | Cancelled; do not issue the request |
| same cancellation events | Submitting | CancelPending; registration may be in flight, so latch a mandatory post-registration cancel |
| same cancellation events | Registered | Cancelled; enqueue exact takeId/callback cancel on independent command lane |
| same cancellation events | CancelPending/Cancelled | Idempotent; never extend grace or create another request |
| same cancellation events | Finished(callback) | Keep delivery terminal; if submit is still in flight, latch exact post-return cancel; otherwise enqueue exact cancel for any server tail. Retired server entry no-ops. Do not rely on owner-close while keepalive retains it |
| synchronous request returns | Submitting | Registered, unless a terminal/cancel transition already won |
| synchronous request returns | CancelPending | Cancelled; send/re-send exact cancel after registration |
| synchronous request returns | Finished/Cancelled | Preserve terminal delivery; NEVER overwrite it with Registered. Fulfil a latched exact cancel before retiring this return obligation |
| result/error/failure callback, through existing PostingSpeechListener | Submitting/Registered | Finished(callback) once; post current listener; SpeechWait/arbiter still decide user acceptance |
| result/error/failure callback | CancelPending/Cancelled | Drop obsolete delivery; preserve pending cancel obligation until submission returns |
| duplicate callback | Finished | Drop duplicate; no second listener or persistence mutation |
| cancellation cannot be queued/delivered | CancelPending/Cancelled | Keep local revocation, record local control failure; no claim of native retirement; existing death/original-deadline policy remains |
| callback before submit was issued | Prepared | No legitimate producer found: the private callback Binder has not been sent; refuse/drop, do not finish a take |
| synchronous request throws, existing Coordinator975-984 path | Submitting | Finished(throw); preserve exception propagation and best-effort exact cancellation if registration may have occurred |
| synchronous request throws | CancelPending | Cancelled; keep best-effort cancel obligation, propagate to existing stale-attempt/exception handling |
| request throws after callback/other terminal transition | Finished/Cancelled | Preserve winner; propagate without reopening or changing a replacement attempt |

Proxy close atomically revokes every active submission and drains its already-issued registration/cancel obligations. It does not wait on main. Keep the cancellation lane usable until submitting entries have run their return/throw cleanup and queued any required cancel; then shutdown drains queued commands. Remove completed proxy registration bookkeeping without invalidating the one SpeechWait-owned answered-tail handle, but never discard a CancelPending entry before its post-registration cancel has been attempted and its success/failure recorded. Callback Binder death is a server-side job event, not proof that a living client's local submission reached a particular state.

### 3.2b Keep blocking input work on the one guarded worker

The Binder entry registers its exact request and queues it without reading the file. Move exists/length/oversize classification onto the same owned worker as file reading and decoding. The previous inline missing/oversize failure becomes an asynchronous worker callback with the same reason/detail. This deliberate timing change closes the unguarded synchronous file-I/O scope; it is not an ABI or final-text change. Keeping metadata on Binder would require a second multi-thread admission lifetime, so reject that alternative. Transport exceptions from the synchronous Binder invocation still propagate unchanged to the existing client catch paths.
Because actual file length is not known when the worker starts, guard the WHOLE task initially with the existing maximum supported audio bound: transcriptionBoundMs(RecordingLimits.MAX_AUDIO_BYTES), currently325000ms. After reading metadata, tighten to the original exact audio-sized bound measured from that SAME task start; do not restart or extend it. Reuse AsrWatchdog/EngineDeadline for both maximum containment and exact remaining deadline. If the exact deadline has already elapsed, publish ending and run no native/delivery work. Preserve ordinary LOAD60s, RELEASE10s, exact requestBoundMs+decodeGrace and the main-side original deadline. All metadata, file IO, conversion, decode, delivery/refusal and cleanup now lie inside the whole-task bound, including legacy/null-callback requests.
Queued cancellation need not cancel a useful open-owner LOAD. Revoke queued work atomically; remove it where the executor allows, and make any unavoidable scheduling wrapper inert BEFORE watchdog/model admission. Retirement cannot be inferred from a Future done flag while a body may still run. An already-claimed task retires only after its actual input/native/delivery/cleanup body exits. Preserve every active entry, including reused legacy callback/take pairs, rather than overwrite an older entry. Current cancellable production requests allocate fresh callback identity; no stale-cancel guarantee is claimed for a hypothetical new client deliberately reusing that identity for a different request.
OWNER-CLOSE's generation barrier includes all old registered/active/queued work, delivery tails and actual model free. It cannot advance a new LOAD while an old close grace can still expire. The new asynchronous missing-file callback may wait behind useful loading or earlier native work; existing main expiry/cancellation still wins. Verify the archived callback client under the qualified setup and report this timing delta rather than claiming its former inline path survives.

### 3.3 Scoped cancellation through the actual model

Migrate the internal model/recipe path and its JVM rigs to one cancellation-aware invocation contract. All three retained binder transcription methods enter that same path, including legacy/null-callback requests; there is no parallel uncancellable model implementation retained for hypothetical clients. Each invocation owns two RunOptions: preprocessor/encoder options retain cpu arena shrink configuration; decoder options do not add shrink. Replace the model-lifetime run options with this invocation-owned scope; do not keep a parallel legacy option/control path or carry an old flag into the next invocation.
Cancellation sets the request token and requests termination of both live option handles through a short lifetime-protected scope. Serialize publication/termination versus detach/close; never close native handles concurrently with setTerminate or model execution. RunOptions.setTerminate is the sole intentional off-lane native-control call, through that lifetime protection; it must not wait for the worker's running decode. The native worker alone creates and closes results/tensors/options/sessions and runs models. No session/model close or options close occurs on Binder/deadline threads.
Check cancellation before/after file read and PCM conversion, around preprocessing/encoding, and in decoder/finalization/window/repair loops. All three retained Binder transcription methods create a fresh invocation scope and enter the same model/recipe path; when cancellation is not requested, prior recognition/error behavior remains. Internal model/JVM callers migrate together; only positively observed transport descriptors remain. Whole-task retirement follows every native/tensor/options cleanup and any delivery/sweep work; it is distinct from native return used to measure invocation termination.
Use an internal typed cancelled outcome before the generic Exception -> DECODE_FAILED path. Drop cancelled results; do not manufacture empty text, normal failure telemetry, successful delivery or legacy-model cleanup. Normal successful final requests retain existing delivery/sweep semantics. Old/null-callback native worker requests retain the original task guard; metadata admission is now inside the same whole-task guard as stated in section3.2b.

### 3.4 Two containment scopes, one deadline authority

Propose 1,000ms scheduled retirement grace, NOT a measured kernel bound or public speed promise. It is a containment budget shorter than the existing 5,000ms decode grace and 20,000ms short-request base, leaving room for the existing reconnect path; those constants do not prove healthy cancellation is fast. A healthy running-decode qualification with the owner explicitly retained must retire/reuse without process kill. This is conditional component evidence, not a promise that an ordinary first cancelled take earns a residency hold. Closing an owner during LOAD can require the bounded kill path because session construction has no demonstrated RunOptions cancellation; report it separately, without a warm-reuse claim. Reject/revise if healthy decode cancellation fails.
JOB grace begins once cancellation owns an active task and spans its actual whole-task retirement, including native/tensor/options cleanup. Registered-but-queued cancellation can retire without running native work or cancelling an open owner's useful LOAD only when later owned work is atomically prevented from starting. Repeated cancel never extends grace.
OWNER-CLOSE grace begins at close and spans any active LOAD/input/decode/delivery tail, queued RELEASE and actual old engine free. It does not stop merely when LOAD returns. Normal open-owner model loading keeps its existing load bound; a new Record alone does not cancel that useful load.
Reuse EngineDeadline's first-wins handles. Retirement/free cancels the relevant grace; expiry owns process ending. If worker completion loses to expiry, AsrWatchdog must already report ending before any next job/generation is admitted, even when the scheduler is paused between winning expiry and its kill action. A stale grace cannot kill a later healthy request/generation. Current EngineDeadline40-42 can win expiry before AsrWatchdog26-28 publishes wedged, so unchanged reuse alone is insufficient. Make the expired first-wins handle visible through this same authority before next admission, even when its kill callback is paused; do not add a second timer/ending owner.
The 1s job grace begins at server-side cancellation ownership; a cancel command that cannot reach that server still relies on the original task/death bound, not an invented host-side1s guarantee. A noncooperative operation uses the existing process-ending fallback; no new model opens while old native work survives. The existing original task bound remains an upper safeguard, never extended. Main does not wait for this on a UI/Binder thread. Current final SpeechWait deadline/retry count are unchanged.

### 3.5 Model and binding boundaries

Actual ModelSwap.exclusive still closes the gate, revokes all registry bindings, and proves engine binder death/process absence before folder writes. Per-job cancellation is not a substitute for that barrier; loaded/mapped sessions survive job retirement. Setup warmup, keepalive and polish qualification retain existing revocation behavior.
A future recovery model-use permit may overlap a live-take permit while the native owner serializes work, but this slice adds no replay permit/purpose. A future preview reuses the current take's speech binding. Neither foundation nor a future handoff may manufacture successful-use notifications to obtain a hold. Preserve the actual existing takeStarted/transcriptArrived/takeEnded routing.

### 3.6 Residency qualification, without a new retention policy

SpeechModelKeepAlive63-141 and the production host adapter DictationSessionService153-163 establish the boundary: only an accepted nonblank ASR answer (Coordinator944) earns this take's hold. takeEnded83-94 releases when Immediately is selected or no this/earlier hold exists. An earlier Forever or unexpired timed hold may remain; an expired timed hold releases. Bind refusal/loss, memoryCritical and ModelSwap revocation can also remove the hold, and Android may reclaim a waived-priority service. None is converted into a guaranteed warm-reuse outcome.
Acceptance distinguishes: (1) cancellation with no prior/this-take earned hold; (2) a real prior or this-take accepted nonblank transcript earning an existing hold; (3) Immediately. Assert cancelled-text suppression and correct next-take text in all three. Require same-model reuse only while existing policy and actual binding lifetime retain it. For unload/reload observations, release unrelated test bindings first; otherwise observe the keepalive decision separately from service lifetime. Include earlier timed-hold expiry, setting change, bind loss/refusal, low memory and swap revocation in the existing keepalive rigs, without changing their policy. Never call speechModelUsed/transcriptArrived for cancelled or preview/recovery work just to make a test warm. An actually accepted nonblank ASR answer still earns its normal hold even if the user later cancels during polish; no notification is fabricated. The direct-model/extra-binding physical fixtures prove retained-owner capability only; they do not substitute for ordinary recorder residency cases.

## 3b. Ownership justification

Cancellation/job lifetime stays in RecognizerOwner/AsrWatchdog/TdtModel because they already own native admission and resource lifetime. Submission/cancel transport stays in PipelineBindings; per-take acceptance stays in SpeechWait/Coordinator. Alternative: a new manager or main-process replay kill barrier; rejected because it duplicates engine authority and forces routine model reload. Actual swap and noncooperative failure still retain process death proof.

## 8. Caller-visible signals audit

Request identity is exact takeId plus callback Binder, not takeId alone. A prepared handle being present freezes this attempt's identity; it means neither registered nor native-started. Current source clients use this one contract; the retained v1 entry does not expose a handle. Cancel requested/accepted does not mean retired. Native return is not whole-task retirement. Owner freed means old model/results/options are gone and close-grace cancellation won, not merely onDestroy returned. Watchdog ending means no new work despite a delayed kill. Missing/null legacy callback means no death notification, not permission to cancel all. isReady must remain false after close/ending. Callback result is still subject to SpeechWait's accepted attempt and the publication arbiter. No new History/clipboard/preview/recovery signal is present.
