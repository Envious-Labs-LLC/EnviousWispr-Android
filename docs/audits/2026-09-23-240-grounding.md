## D. Recommended design

- Give Sentry one owned schema mapping **surface and key to shape**, separate from the PostHog schema.
- Accept event and breadcrumb messages only from declared diagnostic tokens.
- Validate each tag, extra, breadcrumb datum, and map-context value against its key’s declared shape; redact unknown keys or shapes.
- Use finite vocabularies for reason, outcome, defect, and other fixed tokens; validate UUIDs and numeric ranges separately.
- Validate exception types as class identifiers from approved namespaces, and frame fields as code symbols, filenames, or approved library locations. Keep messages and frame values out.
- Explicitly clear or validate user, category, fingerprints, typed contexts, and remaining SDK text fields at the final event seam.
- Replace arbitrary pending `detail` text with a declared reason token.
- Make an added call-site key fail a typed builder or exhaustive schema test until its shape is declared.

This enforces the project’s [no-content-in-diagnostics rule:68](</Users/m4pro_sv/Developer/EnviousLabs/EnviousWispr-Android/.claude/rules/kotlin-patterns.md:68>).
