   170	## 3. Design
   171	
   172	1. **`PreferenceRead` (proposed), in `SessionPreferencesSource.kt`:** `sealed interface` with `Pending` (proposed),
   173	   `Fresh`, `Failed(val reason: String)` (the reason is a content-free token: `exception:<SimpleName>` or
   174	   `timed_out`; never a message, `#194` territory). Two fields, `settingsRead` (proposed) and `termsRead` (proposed),
   175	   `@Volatile`, start `Pending`.
   176	2. **The collectors:** on first emission set `Fresh` and complete the deferred (as today); in the catch set
   177	   `Failed(exception:<name>)` and complete the deferred (today's catch only logs). The fields keep the last
   178	   good values; a first-run failure leaves the constructor defaults (`CleanupOptions()`, empty terms,
   179	   `clipboardPolicy = null`, auto-stop off, `InputDevicePick.AUTO`, tips on, earbuds hold on).
   180	   A reader whose flow COMPLETES before its first emission (coverage B1) answers `Failed(completed_without_value)`
   181	   at once from the collector's normal exit, never staying `Pending` until the bound.
   182	3. **`awaitAnswers(boundMs)` (proposed) replaces `awaitReady`:** each reader's answer is a
   183	   `CompletableDeferred<PreferenceRead>` completed EXACTLY ONCE by its collector, after the emitted fields are
   184	   written: `Fresh` on the first emission, `Failed(exception:<name>)` from the catch,
   185	   `Failed(completed_without_value)` from a normal exit with no emission. The bound never writes the reader:
   186	   `withTimeoutOrNull(boundMs) { deferred.await() }` returning null is the CALLER's `Failed(timed_out)` for
   187	   THIS take, so a late first emission still completes the deferred as `Fresh` for later takes, and a race
   188	   between the bound and the first emission has one winner per take with no torn state (round G1.1). Later
   189	   emissions update the cached fields for later takes and never rewrite an answer. Returns a
   190	   `PreferenceStart` (proposed): `settings: PreferenceRead`, `terms: PreferenceRead`. It never returns "not
   191	   ready".
