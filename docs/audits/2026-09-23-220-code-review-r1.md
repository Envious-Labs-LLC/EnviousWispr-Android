FINDINGS

**MEDIUM | `ListenerSlots.kt:56–72`, `AudioCaptureService.kt:993–994`.** `clearAll()` clears the listeners but leaves their epochs open. A queued binder registration can arrive after `onDestroy`, refill a slot, and receive an event still draining from `TakeEventPublisher`. The destroy test checks only the immediate clear.

Exact drop-in code:

```kotlin
private var closed = false // guarded by lock

fun clearAll() = synchronized(lock) {
    closed = true
    openEpochs.clear()
    epochByIdentifier.clear()
    slots.forEach { it.clearOwnedByLocked(null) }
}
```

At the start of `Slot.register`, under the same lock, add `if (closed) return@synchronized false`. Extend `destroyClearsEverySlot` to attempt both legacy and take registrations after `clearAll()` and assert that both are refused.

The production take commands still reach the existing recording and warm-hold functions. The legacy AIDL is unchanged. I did not run the supplied test receipts or the pending device test.

AMS retains a binding record for each unique identifier until the service is destroyed ([AOSP binding map](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/core/java/com/android/server/am/ServiceRecord.java#1490)). An idle gap ends the warm hold, but continuous takes have no fixed record-count bound; memory impact is **NOT VERIFIED**.
