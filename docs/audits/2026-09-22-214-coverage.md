The claim “a correct blank engine answer implies a blank owner floor” is false. The engine and owner have separate language detector instances, and the source explicitly says their answers can differ.

Concrete counterexample:

- Input: `um uh`
- Engine confidently detects English, so cleanup removes both words and returns blank.
- Owner abstains or detects another language, so cleanup removes `uh` but keeps `um`.
- Engine answer is correctly blank while owner floor is `um`.

Vocabulary restoration order and cleanup options are otherwise equivalent on both sides. Spoken emoji and punctuation use the same option bits, but their application is also language-gated. `TOO_SHORT` cannot carry blank because the blank exit precedes the short-input check at `PolishPipeline.kt:43-50`.

Exact replacement:

```text
The engine and owner use the same frozen cleanup options and the same effective vocabulary order: restore before cleanup, then restore the published result. They do not share one language answer. Each process owns a separate detector, so one may confidently detect English while the other abstains or detects another language. Spoken punctuation, spoken emoji, English-only structured rewrites, and the `um` filler therefore need not produce identical text on both sides. A correct blank engine result does not imply a blank owner floor. `TOO_SHORT` is not a blank-producing reason because the pipeline exits on blank before checking length.
```
