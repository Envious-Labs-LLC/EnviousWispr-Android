## User rubric

Diana Foster is writing a Gmail handoff on her phone between meetings. She wants “the same signature I use on my Mac.” She imports her existing file once and speaks the keyword in the draft. Gmail, Messages and WhatsApp are representative destinations. Examples include “backslash my email,” “Please use backslash my email address,” “backslash sign off,” “backslash stamp” and “I forgot my email address.” The last one is ordinary dictation. Success is the right content at the caret, including spaces and line breaks. A near-match inserting her signature unasked, or a clipboard template silently dropping a copied reference, would break trust. Her workaround is opening the saved template and pasting by hand. Control comes from her editable keyword and explicit saved triggers.
Priya needs exact technical text, Marcus his own punctuation, Diana her draft and Aaron minimal taps. Elena needs saved expansions kept out of AI requests for the take that fires them. Meera needs working examples and Frank a predictable way to find and remove them.

## 0–2. Outcome and scope

Bring the Mac's management, matching, transfer and finalization behavior to Android. Hold the public release until platform differences are either qualified or expressly accepted. Reuse the existing dictation owner and the user's current keyboard. Audio models, cross-device sync and an alternative keyboard are independent features.

## 3. Design and ownership

1. **Store and manage.** Put Snippets in the app navigation and Settings Search. Match Mac add/edit/delete, search of both fields, starter badges, keyword editing, imports and export. Keep a dedicated versioned snippet document in app-private storage so short, large or corrupt lists stay isolated from settings and existing History. Use one main-process repository and the platform atomic file primitive. Serialize all read/modify/write operations on an I/O lane, publish a new immutable list only after durable replacement, distinguish a missing file from failed reads, and never overwrite an unreadable file on open. Seed starters once. Do not reuse the Dictionary's fuzzy matching or tab-separated transfer format.
2. **Expand before cleanup.** Read one coherent snippet inventory at processing. Match against the original transcript before any vocabulary replacement, casing or cleanup can change a trigger. Select the longest full match first. If it requires an unavailable clipboard, preserve that whole phrase, advance past its full match and continue with other independent triggers. Never let a shorter trigger take its place. Keep raw ASR separately as History's original. Hold resolved expansions and markers in the main process. Send only the masked text to the existing processing service, whether local or cloud. Use the same masked input on the deterministic fallback. One snippet finalizer owns marker validation, punctuation and restoration for both live publication and the existing recovery transform. Restore the exact saved text at the last common output boundary after every optional text transform, before anything writes a final History row, copy or insertion. The no-match path uses ordinary preparation. Take cancellation discards pending work.
3. **Protect each result.** Validate every marker against input and resolved expansion content, against each other and against the processed result. On marker loss, duplication or a damaged deterministic result, use the latest intact masked stage and restore it. The unmodified matched transcript with its expansion records is the final safe floor. Match Mac's punctuation, including when the recognizer or processor adds it. Preserve original text as dictated. Carry the fact that a snippet fired to insertion so normal cursor casing or seam deduplication cannot rewrite the saved expansion. Compare final destination spacing separately from the pre-paste Mac reference. AppShell hands History finalText plus the current smart-insertion preference to insertFromHistory, which forwards it to the same insertion runner. Store a compact delivery mode with finalized snippet rows and rescued rows so a History retry keeps the same literal behavior after restart. Older rows keep the existing insertion policy. Reuse the existing non-smart payload branch on both commit and paste. For snippet takes only, match the Mac delivery boundary: in a word-spacing language (including unknown), append a single ASCII space only when the payload does not already end in one. Unsegmented languages keep the exact payload. This space is outside the saved expansion. The shared insertion planner owns only editor spacing. History final text and a direct no-editor copy use the restored, unpadded text. For a real paste attempt the runner first stages its editor payload on the clipboard. Keep the existing ownership branches: if still ours it may restore or rewrite, if another clip is visible leave it alone, and if unreadable leave the staged value alone. That value may include the editor-only trailing space. This applies whenever paste staged text, including successful paste with restoration off, unavailable or declined, and a later retry that commits after an earlier staging attempt. Ownership belongs to the runner irrespective of the eventual editor route. Make no unconditional clipboard-content promise after staging. Do not add snippet-specific clipboard repair. Use Mac CursorInsertionRepair.legacyPayload as the reference.
4. **Dynamic values and replay.** Freeze one instant, system language, calendar and time zone for date and time in one dictation. Text substituted for a placeholder is literal and never scanned for another placeholder. Read the clipboard only for a fired clipboard template. Exercise the documented focused-app path on a disposable phone. Keep the normal recording gesture and delivery. Do not add a clipboard confirmation, change the keyboard, or take focus from another app. Support the standard clipboard read only in contexts where Android permits the result to be distinguished from an inaccessible clipboard. In a background editor keep the affected whole template out of expansion, retain its spoken words, and explain the limitation in the editor/import preview. Preserve the stored placeholder across export. An unavailable clipboard fill-in is an accepted platform difference. Date and time continue to work without it. Ordinary stored snippets need no clipboard read. When no editor is available and the existing fallback copies, use the normal Copied feedback for the restored expansion. On interrupted-audio replay use the current snippet library and the existing History-only deterministic route. Never expand already resolved History/rescue text again.
5. **Transfer.** Accept Mac Snippets v1, compatible pasted lists and CSV through the reviewed preview. Bring in supported TypeWhisper backup rows after validating the actual export shape, enabled status and supported tokens. Preserve exact expansion bytes after decoding, including final newlines. Skip duplicates visibly, review selected additions, assign fresh IDs as Mac does and perform one atomic write against a still-current reviewed list. Preserve the local keyword and reject future/incompatible formats with an actionable message. Use the Mac format for Android export and independently open an Android-authored file on the Mac.
6. The existing session owns when to prepare/publish. A snippet processor owns only the masked take and its restoration. No new speech service, clipboard monitor, background poll or retry loop. Keep saved content and fill-ins out of automatic reports. Large expanded strings must follow the existing safe size limits of delivery, including binder transactions, with confirmed recovery before claiming success.

## 4–9. Contracts, lifecycle and fallback

| Producer or transition | Consumer and required behavior | Failure and retry |
|---|---|---|
| Open, save, edit, delete, import | The screen and next matcher read only the last committed version. Search never writes. Concurrent reviews cannot overwrite another edit. | Show storage errors, retain original file, retry on an explicit action. |
| Dictation in flight, while Settings changes | A coherent current store is used for the match. The selected expansions stay with that take. A new take cannot receive old results. | No store or failed read leaves ordinary dictation usable. |
| No trigger, partial match or unsupported placeholder text | Use Mac behavior for each source. Typed ordinary words pass through. | No false success notice, no clipboard read. |
| Local/cloud polish, rejected/empty output, process death or timeout | One finalized text with exact saved literals for successful matches. If polished markers change, reject that version. | Use the latest intact result and record the true polish outcome. |
| Clipboard fired, empty, textual, non-text or inaccessible | Resolve once under the user's intended action, freeze the chosen value. Distinguish a real empty input from denied focus. | A denied read preserves the original spoken trigger for the affected match. The ordinary no-editor fallback can still write the final result to the clipboard. Verify both paths separately. |
| Live insertion, paste fallback, History save, late save, rescue | All final consumers see restored text. The original transcript stays independently available. | One original target and one write. Preserve existing visible fallback if that target is lost. |
| Interrupted audio, foreground replay, stored-text re-insert | Audio replay matches against the current library. Stored final text is delivered without matching it a second time. | Preserve the existing recorded words and save/replay authorization. |
| File picker cancelled, malformed/future file, changed review | No saved changes. Reviewed additions are committed together with their order and literal text. | Explain stale or unsupported input, provide a fresh review on the user's action. |

Persist entries, keyword, seed state and committed revision together. A temporary marker is private to the active processing call. Content-free outcomes may use existing telemetry only where needed for an existing route. A masked result must never be mistaken for a deliverable result.

## Implementation checks

The emulator confirmed one spoken multiline command in Messages and its no-editor clipboard fallback. The Android system showed its clipboard preview. The app's existing notice policy suppresses successful no-target copies, so explicitly announce a copied snippet through that same notice owner. A quoted pasted row with both a list separator and a comma can become a different trigger if guessed as CSV. Ask the user to choose for this ambiguity and retain a literal quote inside an unquoted CSV field, matching the Mac reader. An over-limit manual entry could otherwise export a file that cannot be restored. Validate manual saves, reviewed merges and export snapshots against the same existing Mac transfer limits. The existing snippet and coordinator suites are the simplest regression checks for these supported user actions, under the testing rules for reproducible customer harm and fixture placement. Confirm an ordinary date/time template independently of the unavailable clipboard template.
