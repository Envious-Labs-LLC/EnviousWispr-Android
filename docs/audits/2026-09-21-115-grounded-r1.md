## FACT: the-text-pipeline
Each stage returns text plus an outcome. A stage may enrich text; it may never erase the last valid result.

1. ASR produces raw text and an observed language.
2. Deterministic cleanup applies filler, number and punctuation rules.
3. Vocabulary correction applies exact terms, aliases, case rules and priority.
4. Optional polish runs, local or cloud, under the policy snapshot the session carries; the answer is one
   `PolishOutcome` per request, with a `PolishReason` from a closed set.
5. Output safety rejects blank, truncated, duplicated or meaning-shifted results and falls back.
6. Insertion planning handles capitalisation, spacing, seam de-duplication and the replacement range.
7. Accessibility returns to the tracked editor and picks ONE route before writing: on API 33+ with an
   eligible field it commits through the accessibility input connection (no clipboard, no "Copied"
   toast); otherwise `ACTION_PASTE`; otherwise copy-only with a visible Paste action. It writes once,

# Architecture Rules

Instructions only. The map — modules, packages, processes, pipeline, sources of truth — is
[`../knowledge/architecture.md`](../knowledge/architecture.md). The design target is
[`docs/enviouswispr-android-architecture.md`](../../docs/enviouswispr-android-architecture.md); the outcome
contract is [`docs/enviouswispr-android-parity-spec.md`](../../docs/enviouswispr-android-parity-spec.md).
**Both describe where we are going and name types that do not exist. Grep before citing one.**

## FACT: the-laws
| Law | Why |
|---|---|
| Heart path is sacred. | No optional feature may prevent the user getting their words. |
| Process boundaries are real boundaries. | `:audio`, `:asr` and `:polish` bound memory and crash blast radius. |
| Convenience is not justification. | "Easy to wire here" is invalid placement. |
| New shared objects are guilty until proven innocent. | Every coordinator, manager and singleton justifies its existence. |
| Engine independence lives at the adapter seam. | One session owner, never one per surface. |
| Structural drift is a bug. | Architecture regression is correctness debt. |
| Shortcuts must be declared. | Disclose every temporary compromise in the change summary. |

## FACT: heart-and-limbs
**Heart:** trigger, capture, ASR, text finalization, insertion. It must always complete.
**Limbs:** deterministic cleanup, vocabulary, local polish, cloud polish, live preview, history.

**The fallback floor is the LAST SUCCESSFUL TEXT, not raw ASR.** Cleanup and vocabulary run before polish
precisely so their result survives a polish failure. Only empty output falls through to raw ASR.

A limb hands back the last good value. Never an exception that unwinds the session, never `null` where the
caller has no slot for it, and never an empty string as a failure signal — empty is a legitimate
transcription of silence and the caller cannot tell them apart.

Before adding a feature: heart or limb? Owning package? Owning process? Failure mode? Can the heart
continue? Fuzzy answers mean blocked.

## RULE: one-owner-for-the-session
Every entry point issues COMMANDS to one session owner. No surface runs its own recording, transcription,
polish or insertion, and no surface invents its own phase; each renders the owner's state.

When the coordinator replaces today's session service, it lands in one change — old code removed, new code
wired, no shim (`GR-MIGRATION-COMPLETE`).

## RULE: aidl-is-append-only
Reordering, renaming, or changing a parameter list breaks an already-installed app at RUNTIME with no
compile error. Append at the end. To change a signature, bump the interface and keep the old one until
nothing binds it. The separately installed client this protects is the instrumentation APK
(`app-debug-androidTest.apk`), which binds the non-exported services and is not replaced when the
production APK is, so "both ends ship in one APK" is not a reason to delete a transaction.

## RULE: keep-central-types-thin
A multi-domain owner delegates downward, holds minimal state, exposes a narrow surface, and has a
one-sentence purpose. Block unrelated-domain knowledge, and state plus orchestration plus business rules
in one place.

**`ui/AppShell.kt` and `ui/DictationSessionService.kt` are the standing extraction targets.** Take the
sizes rather than citing a count:

```bash
wc -l app/src/main/java/com/envi/wispr/ui/AppShell.kt app/src/main/java/com/envi/wispr/ui/DictationSessionService.kt
```

Growth in either needs a reason and a named extraction target. Add a screen file rather than a section
to `AppShell.kt` (`TranscriptionScreen.kt`, `PolishScreen.kt`, `SettingsPages.kt`, `ModelCards.kt`,
`HistoryScreen.kt`, `DictionaryScreen.kt`, `OnboardingScreen.kt` are the precedent). Since #190 the shell
holds only route state and the exhaustive screen `when`: the top bar, bottom bar, drawer and glyphs are
`AppNavigation.kt` (with `AppRoutes`, the one reader of the saved route names), the shared rows, chips and
glyphs are `SettingsComponents.kt`, and the activity hands the shell one `AppActions` holder of ten
capability groups built inside `remember(viewModel)`; a new callback joins its group, never the root
signature. `ui/AppShellShapeTest` pins all three. The session service's user-facing sentences live in
`insertion/InsertionOutcomeMessages.kt`.

## RULE: isolate-limbs
A limb must not root into app-wide, window, or insertion-orchestration state. Every limb has a deadline, a
failure path, and an unchanged-text fallback.

**Only one heavy inference process is resident by default.** S1-mini and the Parakeet encoder are each
several hundred megabytes; both resident is not a supported state. Unload before switching engines when
headroom is unsafe, and never load a heavy model in the main UI process. Warm-at-connect is the stage 1
default (#72, measured 2026-09-01 on the S26 Ultra only, debug build, so it establishes neither general
S26, release-build, nor other-device safety: a later warm-up did not reduce peak residency and added 0.8
to 3.1 s of wait; table in
`docs/feature-requests/issue-72-2026-09-01-model-residency-decision.md` §11.1.1). The levers that would
reduce residency are releasing the speech model after transcription (#73) and the NPU polish model (#21).

## RULE: gate-on-capability-not-identity-literal
Feature gates read a declared capability, never an engine or provider identity literal. `when (provider)`
is correct only where the behaviour genuinely IS about identity — the privacy disclosure is the legitimate
case.

**Where an identity `when` is legitimate it must be EXHAUSTIVE with no `else`.** A new `PolishProvider`
must break the build at every disclosure and routing site. An `else` turns that compile error into a
shipped wrong privacy answer.

## RULE: own-state-locally
Keep state near its owning domain; never centralise it because many layers read it. The declared sources of
truth are in [`../knowledge/architecture.md`](../knowledge/architecture.md); **a second home for any of them
is a bug.**

## RULE: minimize-visibility
Kotlin defaults to `public`, so the default is wrong. Declare `private`, then `internal`. Only a type
crossing a Gradle module boundary needs `public`.

## RULE: protect-audio-asr-stability
Audio and ASR changes prioritise stability, minimise blast radius, keep rollback clear, and attach measured
evidence from the physical phone. UI coupling to service internals is a warning sign.

**Never do work on the audio callback thread.** No allocation, no logging, no binder call, no lock another
thread can hold. Buffer and hand off.

## RULE: no-idle-cost
At idle: no timer, no amplitude poll, no accessibility traversal, no binder call, no wake lock, no resident
model. Audio levels are PUSHED from the capture process during a session, not polled by each surface. The
accessibility service remembers only the last focused editable node identity and ignores our own windows.

A background poll is a battery regression even when it is cheap, because the standard is zero, not small.

## RULE: insertion-fails-safe-never-silently
One route, one write (#141): return to the tracked editor and pick exactly one route BEFORE writing. On
API 33+ with an eligible field, commit through the accessibility input connection (no clipboard, no
"Copied" toast); otherwise `ACTION_PASTE`; otherwise copy-only with a visible Paste action. Judge success
from the editor's own text, never the caret. Never `ACTION_SET_TEXT`.

**A stale, missing or unsupported target keeps the transcript on the clipboard and tells the user.** It
never inserts into whatever happens to be focused now.

## FACT: there-is-no-sensitive-field-guard-and-that-is-decided
**Founder decision 2026-08-28: EnviousWispr does not special-case password, payment or OTP fields.** If
the user dictates into one, we insert. Three reasons, so no session rebuilds it: Google Play's
AccessibilityService policy requires disclosure and forbids autonomous operation but is silent on field
types (verified 2026-08-28); the same shape was killed on
macOS after a probe showed Secure Input does not block our paste; and as built it refused only the
harmless insertion step while putting the transcript on the SYSTEM CLIPBOARD and still sending it to
history and cloud polish.

Rebuilding it requires new evidence and a guard placed where the exposure is (before cloud polish and
before history), never at the insertion step.

**The code has not caught up:** `paste/PasteAccessibilityService.isSensitive` and
`InsertionResults.COPY_ONLY_SENSITIVE` still divert to clipboard-only. Removing them is
[issue #11](https://github.com/Envious-Labs-LLC/EnviousWispr-Android/issues/11), heart path, so it needs
the review gate and a hardware run.

## RULE: models-are-pinned-verified-and-app-private
Every model descriptor carries a pinned revision and every model file an exact byte count and SHA-256;
`isAvailable` refuses anything failing those or whose URL omits the pinned revision. Ready only after on-device verification;
failed files quarantined, never loaded. Files stay in app-private storage — do not reintroduce a broad
external-storage permission.

## RULE: architecture-definition-of-done
Triggers: Gradle modules, process assignment, AIDL surface, a new coordinator, state ownership, package
boundaries, cross-module visibility, or logic moved across layers. Uncertainty blocks work pending Codex
review (`GR-ESCALATE-CONSEQUENTIAL`).

- **Placement** — correct package and process; ownership explained in one or two sentences.
- **Heart** — the user still gets text when every optional feature fails.
- **Anti-god-object** — no convenience logic in `AppShell.kt` or the session service.
- **API** — narrowest visibility; no service internals leaked to UI.
- **Boundaries** — no upward dependency; no UI type reaching a service.
- **Validation** — unit tests green, plus a hardware run for any heart-path change, with the evidence
  named. Untested edges stated explicitly.
- **Debt** — shortcuts disclosed; follow-up extraction named.

Name the `PAR-###` row and the evidence that closes it. Parity is the same user OUTCOME, never a literal
imitation of a macOS mechanism. A row is closed by evidence, not by code existing.

   175	- The audit (REF-04) named the three teardown waits and proposed the queue.
   176	
   177	### 4. Boundaries a naive design misses
   178	- **A binder call has no timeout.** Replacing the polls with a push removes the ASKS; the COMMANDS
   179	  (`stopCapture`, `finishTake`, `startCaptureForTake`) stay synchronous binder calls and can hang the same way.
   180	  The bound therefore watches the WHOLE take (armed at `startCaptureForTake`, disarmed at `onEnded`), and the
   181	  commands run off the main thread (they already run on the owner's scope or the main thread via
   182	  `handleCommand`; §3 A6 says which move to the scope). A hang inside a command on the MAIN thread would
   183	  freeze the app's UI; the plan moves every capture command off main.
   184	- **Process death versus wedge.** `onServiceDisconnected` fires for death; a wedge fires nothing. The bound
   185	  is the only signal for a wedge, and it must be long enough that a slow phone under load never trips it:
   186	  ticks come once a second from the capture loop, which runs at audio rate; three missed seconds is the
   187	  proposal (§3 A5), measured against the emulator's tick gaps in §11.1.
   188	- **The instrumentation client.** `app-debug-androidTest.apk` binds `IAudioCaptureService` by transaction
   189	  number (`architecture-rules.md` RULE: aidl-is-append-only); the new methods are appended after
   190	  `unregisterSpectrumListener`, and the old polled getters STAY (legacy, like `getSpectrumBands`).
   191	- **oneway and ordering.** `oneway` calls from one binder to one listener are delivered in order on the
   192	  receiver's binder thread pool but may run CONCURRENTLY on different pool threads; the owner posts each
   193	  event to its main thread (as `publishLive` already demands) so the sequence is serialised there. The
   194	  ending after the ticks: the owner's `TakeArbiter` and the RECORDING check make a late tick harmless.
   195	- **The file path on the ending.** `releaseSession` closes the file BEFORE the push, so the owner never
   196	  calls `waitForFileReady`; the two `waitForLive` failure paths that call it today are replaced by the
   197	  ending push carrying the path (and `stopAudioService` after).
   198	- **The queue and process death.** A queue in the Application's scope survives a Service's destroy but not
   199	  the process; a write still queued when the process dies is lost exactly as a launched job was. The
   200	  `interrupted` write at destroy is enqueued FIRST in `destroy` (before anything else) so it is the next
   201	  write applied; `TranscriptDao.recoverStaleDrafts` on the next start remains the backstop, unchanged.
   202	- **The clean-stop marker.** `PasteAccessibilityService.onDestroy` marks the stop clean AFTER its blocking
   203	  drain on purpose (a kill during the drain must not read as clean). With the queue, the marker is written BY
   204	  the queue as the last enqueued job, so the ordering survives without the wait.
   205	- **The capture thread owns `AudioRecord` and the file.** `onDestroy` today joins it 2 s and, if still alive,
   206	  abandons the resources to process death (`:750-756`). Without the join the same abandonment happens 2 s
   207	  sooner; nothing else in `onDestroy` needs the thread gone (`stopRecording()` above it signals the stop).
   208	  `waitForFileReady` stays as a legacy AIDL method (append-only) with no production caller.
   209	
   210	### 5. High-risk premises, with evidence
   211	- **P1. A wedged `:audio` hangs the take today.** Staged on the JVM rig: a `FakeCapture` whose `isCapturing()`
   212	  blocks forever leaves the take RECORDING with no ending (a row written first, red-by-today, then green after
   213	  chunk A). On the emulator: `kill -STOP <pid of com.envi.wispr:audio>` mid-take (the disposable emulator; the
   214	  pid read from `pidof` in the same command) leaves the recorder up with no sentence today; after chunk A it
   215	  ends with the wedge sentence within the bound. To be MEASURED before chunk A (§11.1 a).
   216	- **P2. `oneway` pushes from `:audio` arrive while the owner's binder pool is free.** The owner's process is the
   217	  default process; its binder pool serves the paste service and the owner's AIDL. Measured today by the
   218	  spectrum push (fifteen a second, #187, on the phone and the emulator). Not re-measured.
   219	- **P3. One tick per second from the capture loop is regular enough for a 3 s bound.** The loop reads at audio
   220	  rate (`:540-566`); the emulator run records every tick gap over three takes (§11.1 b); the largest gap sets
   221	  the floor the bound must clear by 3x.
   222	- **P4. The two stop-path writes race today.** Evidence: #186's hosted-runner failure (session log 2026-09-20)
   223	  and the row's comment. The build's ordering row uses a fake DAO that applies writes on two threads with a
   224	  staged delay and must go red on 87e07ca.

   228	### A. Push, not poll (chunk A)
   229	A1. **`ITakeListener` (proposed)**, `app/src/main/aidl/com/envi/wispr/audio/ITakeListener.aidl`, all `oneway`:
   230	   `onLive` (proposed) `(boolean forced, int routeKind, int routeReason, long liveAfterMs)`, `onTick` (proposed) `(long elapsedMs)`,
   231	   `onSilenceStatus` (proposed) `(int status)`, `onEnded(int terminalReason, int startFailure, String audioFilePath, int silenceStatus, float takePeakAmplitude, String effectiveInputDevice)`.
   232	   `IAudioCaptureService` appends `registerTakeListener(ITakeListener)` and `unregisterTakeListener(ITakeListener)`
   233	   after `unregisterSpectrumListener`; the polled getters stay, marked LEGACY like `getSpectrumBands`.
   234	A2. **`TakeEventPublisher` (proposed)** in `:audio`, service-scoped like `WarmHoldOwner`, holding one
   235	   `AtomicReference<ITakeListener?>`; every call is `runCatching` (a dead owner must not throw into the capture
   236	   loop) and never waits. Sites: `markLive` path (`:554`, the first buffer after the gate opens) → `onLive`;
   237	   the capture loop → `onTick` when the elapsed second changes (one line, no allocation beyond the binder call,
   238	   on the capture thread AFTER the write: `protect-audio-asr-stability` says no work on the audio callback
   239	   thread; the capture loop is our own reader thread, where the picture is already offered); the detector's
   240	   status change → `onSilenceStatus` (from `DetectorFeed`, where the status is written); the end of
   241	   `releaseSession`, after `closeResources` and `session = null`, → `onEnded` with the reason, the closed
   242	   file's path, the last silence status, the peak and the device label.
   243	A3. **The owner** registers its listener in `startCaptureForTake`'s caller (`tryStartRecording`, next to
   244	   `listenForPicture`) BEFORE the start call, so no event can precede registration; each event is
   245	   `host.postToMain { … }` and then handled by the existing code paths: `onLive` → `publishLive(forced)` with
   246	   the route facts stamped; `onTick` → `updateElapsed`, `publishDurationWarningIfNeeded`,
   247	   `publishMicrophoneNoticesIfNeeded` once (the tip gate); `onSilenceStatus` → `publishSilenceNoticeIfNeeded`
   248	   with the pushed value; `onEnded` → the existing `when (CaptureEnding.fromAidl(reason))` with the path
   249	   handed to `stopAndTranscribe`, `takeFacts.captureTerminal`, `takeFacts.silenceStopStatus`,
   250	   `takeFacts.peakAmplitude` (from the payload's peak, replacing `takePeakAmplitude()`) and `captureDeviceLabel`
   251	   for the row's `captureDevice` (from the payload's label, replacing `effectiveInputDevice()`), with no
   252	   replacement getter call (coverage B1). `startPolling`, `waitForLive`, `DictationPollingThread`, `LIVE_POLL_MS` and the `liveState()`,
   253	   `isCapturing()`, `elapsedMs()`, `terminalReason()`, `silenceStopStatus()`, `inputRouteKind()`,
   254	   `inputRouteReason()`, `liveAfterMs()`, `waitForFileReady()`, `takePeakAmplitude()`, `effectiveInputDevice()`,
   255	   `audioFilePath()` and `lastStartFailure()` members of `CaptureLink` are deleted (`GR-MIGRATION-COMPLETE`);
   256	   `onEnded` carries the start failure code, so the ending-before-live case reads nothing. After the change the
   257	   only synchronous calls into `:audio` are the three commands and the two listener registrations.
   258	A4. **Live wait.** STARTING ends by `onLive` (→ RECORDING), by `onEnded` before live (→ the existing
   259	   `CAPTURE_ENDED_BEFORE_LIVE` / `CAPTURE_START_EARBUDS_REFUSED` by reading `lastStartFailure()` once), or by the
   260	   existing `LIVE_WAIT_BOUND_MS` deadline, now a main-thread `postDelayed` instead of a polling thread.
   261	A5. **The wedge bound.** `TAKE_SILENT_BOUND_MS` (proposed, 3 000 ms, revisited after §11.1 b): a main-thread
   262	   `Runnable` re-posted on every event from the pusher, armed BEFORE the listener is registered and the start
   263	   command is sent, and effective until the binding is released (coverage C1: it covers a start that never
   264	   returns, a registration that hangs, a command outstanding after `onEnded` such as `finishTake`, and a wedge
   265	   after the take moved to PROCESSING or CANCELLING while a capture command was still out); when it fires,
   266	   `handleServiceFailure(TerminalReason.AUDIO_PROCESS_UNRESPONSIVE)` if the take is STARTING or RECORDING, else
   267	   the outstanding command is abandoned and the binding released (the take's words are already in hand)
   268	   (proposed member, `TerminalResult.AUDIO_INTERRUPTED`, sentence in `TakeNotices`: "The microphone stopped
   269	   answering. Try again.", `TelemetryChannels` both sets, `TakeNoticesTest` and `TakeFactsTest` rows), then
   270	   `pipeline.stopAudioService()` and `unbind` (a binder to a wedged process is released, never called). The
   271	   bound is disarmed when the last outstanding command returns after `onEnded`, and by every terminal path's
   272	   release of the binding. No timer exists outside a take (RULE: no-idle-cost). Non-triggers, each a row
   273	   (coverage C2): a long silence with auto-stop OFF (ticks continue; the pusher is the capture loop, not the
   274	   detector), the picture push stopping (a different listener), a STARTING gate open longer than the bound
   275	   (ticks start at the first buffer, BEFORE the gate opens: `onTick` is sent from the loop from the first read,
   276	   live or not), and a paused tick source (the only thing that pauses the capture loop is a blocked
   277	   `AudioRecord.read`, which IS the wedge).
   278	A6. **Commands off main.** `stopCapture()` and `finishTake()` are called from `stopAndTranscribe` and
   279	   `finishTakeOrStop`, which run on the owner's scope today except the cancel path; the plan routes the cancel's
   280	   `stopCapture` through the scope too, so no synchronous binder call to `:audio` runs on the Service's main
   281	   thread (`never-block-a-binder-or-ui-thread`).

   283	### B. The History write queue (chunk B)
   284	B1. **`HistoryWriteQueue` (proposed)**, `history/HistoryWriteQueue.kt`, owned by `ModelBootstrapApplication`
   285	   (one per process; the default process holds the owner and the paste service): a `Channel<HistoryWrite>`
   286	   (unlimited) drained by ONE coroutine on `Dispatchers.IO` in an application `SupervisorJob` scope; each write
   287	   is a `suspend (TranscriptRepository) -> Unit` with a content-free label for the log; a write that throws is
   288	   logged by label and the drain continues. `enqueue` never suspends and never blocks.
   289	B2. The draft INSERT (`:577-595`, today `scope.async` on the owner's scope) is the FIRST queued write of a take
   290	   (coverage D1): it runs on the queue's worker under application ownership, publishes its id to a
   291	   `CompletableDeferred<Long>` the later queued writes await INSIDE the worker, and is never cancelled by
   292	   `destroy` (the owner's scope cancel no longer touches it). `surface.attachTranscript(id)` and the journal
   293	   association run from the same queued job. `updateDraftStatus`, `discardDraft`, `setDraftStatus`'s callers, the
   294	   destroy `interrupted` write and the paste service's outcome write enqueue instead of
   295	   `scope.launch`/`historyScope.launch`; `pendingHistoryUpdates` and the destroy join are deleted. Ordering is by
   296	   ENQUEUE time, on one worker, so a row's writes land in issue order.
   297	   **Writer inventory** (coverage D2, `TranscriptRepository.kt:12-69`): per-take writers are `insert`,
   298	   `updateStatus`, `discard`, `finalize`, `finalizeInsertionOutcome` (the owner and the paste service) and
   299	   they ALL go through the queue; `setKept`, `delete`, `deleteAll`, `pruneWordlessRows` and
   300	   `recoverStaleOpenRows` are the History screen's and the start-up recovery's writers, on their own scopes,
   301	   and stay outside it. The single-writer claim is narrowed to per-take writes.
   302	B3. `asrNotReadyEndsProcessing` asserts `status == asr_error` again; the rig's fake DAO gains a staged-delay mode
   303	   (two worker threads, the first write delayed) that reproduces the race on 87e07ca (P4).
   304	
   305	### C. Teardown without a blocking wait (chunk C)
   306	C1. `DictationSessionCoordinator.destroy`: enqueue the `interrupted` write FIRST (it needs the id: the queue
   307	   worker awaits the draft's deferred), then `serviceJob.cancel()` (no join), then the existing in-memory
   308	   invalidation and release; the `runBlocking` blocks are deleted. The late-polish-callback race the join
   309	   protected against (coverage E1): every finalization write ADMITTED before `destroy` was already enqueued
   310	   before the `interrupted` write, so the queue applies it first and the `interrupted` write lands last; a
   311	   finalization not yet admitted loses the `TakeArbiter` claim to `destroy` and never enqueues. Nothing can
   312	   restore `ready` after `interrupted`.
   313	C2. `stopAndTranscribe`'s `runBlocking { draftCreation.await() }` (`:838`) becomes an enqueued write that awaits
   314	   the id on the worker.
   315	C3. `PasteAccessibilityService.onDestroy`: the outcome write is enqueued (it is a per-take writer); the
   316	   `joinAll` is deleted and `markStopWasClean` is enqueued as the LAST job on the queue. The bubble-position
   317	   saves (`:303`) stay on the service's scope and teardown may discard an in-flight one (coverage E3): the
   318	   position is a preference whose next save wins, and the last landed value is what the bubble reopens at.
   319	   Teardown never calls a synchronous unregister on the audio binder (coverage E4): the listener registration is
   320	   released by `unbindService` alone, on every path, including the wedge.
   321	C4. `AudioCaptureService.onDestroy`: `stopRecording()` signals; the `thread.join(2_000L)` and its branch are
   322	   deleted; the comment's abandonment contract stands from the moment `onDestroy` returns. The interleaving
   323	   where the old capture thread still owns `AudioRecord` when a new take starts in the SAME process (coverage
   324	   E2): `startRecording` refuses while `session != null` (`:328`), and `releaseSession` clears `session` only
   325	   after `closeResources` released the recorder, so a new take cannot open a second recorder while the old one
   326	   is held; a thread parked inside `AudioRecord.read` keeps `session` set and the next start fails with
   327	   `START_FAILURE_OTHER`, which the owner reports as `CAPTURE_ENDED_BEFORE_LIVE`; measured at build by
   328	   `AudioLimbCloseTest`'s stuck-thread row starting a second take.
   329	
   330	**Pipe or bucket.** The leak is created wherever the owner ASKS or WAITS; a bound on the polling thread alone
   331	(the issue's shape 2) is a bucket. Chunk A removes the asks (pipe); the wedge bound is the one bucket that must
   332	stay, because a synchronous command has no timeout at the binder, and it is named as such. Chunks B and C remove
   333	the waits (pipe). Upstream of all three: nothing; the process boundary is the design.

   355	every Service and dies with the process; a write left in the channel at process death is lost as a launched job

   202	     *
   203	     * The abandonment flag is checked at the top of every pass AND immediately after every remote call,
   204	     * because a gap can open while a call is in flight and a verdict computed from the blocks before a
   205	     * gap must never be applied to the audio after it.
   206	     */
   207	    private fun feederLoop(
   208	        pauseSeconds: Float,
   209	        token: Long,
   210	        takeId: String,
   211	        stillLive: () -> Boolean,
   212	        endOnSilence: () -> Unit,
   213	    ) {
   214	        val ring = ring ?: return
   215	        val block = ByteArray(READ_BLOCK_BYTES)
   216	        var started = false
   217	        var reportedAbandon = false
   218	
   219	        fun shouldStop(): Boolean {
   220	            if (detectorAbandoned.get()) {
   221	                if (!reportedAbandon) {
   222	                    reportedAbandon = true
   223	                    DebugLogger.warn(tag, "Auto-stop abandoned for this take")
   224	                }
   225	                return true
   226	            }
   227	            return !stillLive()
   228	        }
   229	
   230	        try {
   231	            while (!shouldStop()) {
   232	                val remote = vadService
   233	                if (remote == null) {
   234	                    Thread.sleep(FEEDER_IDLE_MS)
   235	                    continue
   236	                }
   237	
   238	                if (!started) {
   239	                    // The versioned start carries the take's id as detector context; a legacy start (no
   240	                    // id) keeps the old transaction (issue #176).
   241	                    val status = runCatching {
   242	                        if (takeId.isEmpty()) remote.start(token, pauseSeconds)
   243	                        else remote.startForTake(token, pauseSeconds, takeId)
   244	                    }
   245	                        .getOrElse {
   246	                            abandon()
   247	                            DebugLogger.warn(tag, "Auto-stop unavailable: start failed, ${it.message}")
   248	                            return
   249	                        }
   250	                    if (shouldStop()) return
   251	                    if (status != SilenceVadService.STATUS_READY) {
   252	                        abandon()
   253	                        DebugLogger.warn(tag, "Auto-stop unavailable: the detector reported so")
   254	                        return
   255	                    }
   256	                    started = true
   257	                    silenceStatus.compareAndSet(
   258	                        AudioCaptureService.SILENCE_STATUS_PREPARING,
   259	                        AudioCaptureService.SILENCE_STATUS_READY,
   260	                    )
   261	                }
   262	
   263	                val length = ring.poll(block)
   264	                if (length <= 0) {
   265	                    Thread.sleep(FEEDER_IDLE_MS)
   266	                    continue
   267	                }
   268	
   269	                val result = runCatching { remote.processBlock(token, block) }
   270	                    .getOrElse {
   271	                        abandon()
   272	                        DebugLogger.warn(tag, "Auto-stop unavailable: the detector call failed")
   273	                        return
   274	                    }
   275	
   276	                if (shouldStop()) return
   277	
   278	                when (result) {
   279	                    SilenceVadService.RESULT_SILENCE -> {
   280	                        // endTake re-checks that this session is still the live one, under the lock, so
   281	                        // a verdict from a finished take cannot end the take running now.
   282	                        endOnSilence()
   283	                        return
   284	                    }
   285	
   286	                    SilenceVadService.RESULT_UNAVAILABLE -> {
   287	                        abandon()
   288	                        DebugLogger.warn(tag, "Auto-stop unavailable: the detector gave up mid-take")
   289	                        return
   290	                    }
   291	                }
   292	            }
   293	        } catch (interrupted: InterruptedException) {
   294	            Thread.currentThread().interrupt()
   295	        } catch (e: Exception) {
   296	            abandon()
   297	            DebugLogger.warn(tag, "Auto-stop unavailable: the feeder failed, ${e.message}")
   298	        } finally {
   299	            if (started) runCatching { vadService?.finish(token) }
   300	            unbindVad()
   301	            if (feederThread === Thread.currentThread()) feederThread = null
   302	        }
   303	    }

   306	     * Auto-stop is off for the rest of THIS take, and is never resumed within it.
   307	     *
   308	     * The status it lands on records whether the detector ever worked. A take that never got one tells
   309	     * the user; a take that had one and lost it does not, because that recording is still correct and a
   310	     * message part way through is an interruption for nothing.
   311	     */
   312	    fun abandon() {
   313	        detectorAbandoned.set(true)
   314	        while (true) {
   315	            val previous = silenceStatus.get()

   317	                AudioCaptureService.SILENCE_STATUS_DISABLED,
   318	                AudioCaptureService.SILENCE_STATUS_UNAVAILABLE,

   320	
   321	                AudioCaptureService.SILENCE_STATUS_READY -> AudioCaptureService.SILENCE_STATUS_LOST_AFTER_READY
   322	                else -> AudioCaptureService.SILENCE_STATUS_UNAVAILABLE
   323	            }
   324	            if (silenceStatus.compareAndSet(previous, next)) return
   325	        }
   326	    }

   341	     * Read [status] BEFORE calling this, because abandoning can move it.

   350	            feederThread?.let { runCatching { interrupt(it) } }
   351	        }
   352	        if (unbindNow) runCatching { unbindVad() }
