## Known-problem check

1. **Humble Object:** Known fix. Keep the framework-owned object minimal and move logic into a plain object. Main failures are untested adapter wiring, lost thread semantics, and interaction-heavy fakes that merely copy implementation. The plan uses the correct shape and retains device UAT for the real boundaries. [Canonical source: Fowler](https://martinfowler.com/articles/humble-dialog-box.html), [Android local-test guidance](https://developer.android.com/training/testing/local-tests).

2. **AIDL in JVM tests:** `Binder()` itself does not throw in this build’s mockable `android.jar`; the generated `Stub` constructor calls `attachInterface`, which throws “not mocked.” AIDL `Default` is a no-op/default-valued implementation with `asBinder() == null`, intended as a default/fallback implementation, not a functioning Binder callback. The plan’s Kotlin links correctly avoid both Binder and default-value traps (`docs/feature-requests/issue-186-2026-09-20-session-coordinator.md:211-223`). [Android AIDL](https://developer.android.com/develop/background-work/services/aidl), [AIDL generator](https://android.googlesource.com/platform/system/tools/aidl/+/dd0d78f0ead984881caee291751226001f92587e/generate_java_binder.cpp#913).

3. **`Main.immediate` replacement:** A single-thread executor preserves serialization, but not inline execution when already on the owner thread, nor Android’s Looper queue. `Main.immediate` explicitly avoids redispatch; ordinary dispatchers default to dispatching. The production default is correct, but the proposed JVM stand-in is not faithful. [Kotlin `Main.immediate`](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/-main-coroutine-dispatcher/immediate.html), [`isDispatchNeeded`](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/-coroutine-dispatcher/is-dispatch-needed.html), [Android `Handler`](https://developer.android.com/reference/android/os/Handler).
